<summary>OS 간(Mac ↔ Windows/Linux)의 한글 처리 표준 차이로 인해 발생한 지극히 정상적인 호환성 문제</summary>
💻 코드 전/후 비교
 
```python
# ❌ 변경 전 (에러 발생 코드)
top = rel.parts[0]

# 🎯 변경 후 (정답 코드)
top = unicodedata.normalize("NFC", rel.parts[0])
```

💡 왜 이렇게 사용해야 하는가?

1. [0] (인덱싱)을 붙여야 하는 이유
	• rel.parts는 ('공용', '규정', '문서.pdf')처럼 모든 하위 폴더와 파일명이 담긴 묶음(Tuple) 데이터입니다.
	• 딕셔너리와 비교하려면 최상위 폴더 이름 딱 하나만 필요하므로, 첫 번째 값만 쏙 빼오기 위해 [0]을 반드시 붙여야 합니다.
2. unicodedata.normalize("NFC", ...)을 감싸야 하는 이유
	• 맥(Mac) 환경에서 만든 폴더명은 구글 드라이브에 올라갈 때 한글 자음과 모음이 쪼개진 NFD 방식('ㄱㅗㅇㅇㅛㅇ')으로 저장됩니다.
	• 반면, 파이썬 코드에 입력한 딕셔너리 키는 완성형 한 글자인 NFC 방식('공용')입니다.
	• 컴퓨터는 두 글자를 완전히 다른 데이터로 인식하여 UNKNOWN을 뱉기 때문에, 쪼개진 한글을 완성형으로 강제 결합해 주는 normalize("NFC", ...) 과정이 필수적입니다.

### 1. LLM 오케스트레이션 프레임워크 (라마인덱스 vs 랭체인)

AI 앱을 개발할 때 데이터를 다루는 목적에 따라 두 도구 중 하나를 선택하거나, 함께 혼용하여 사용합니다.

| 구 분 | 라마인덱스 (LlamaIndex) | 랭체인 (LangChain) |
| --- | --- | --- |
| **핵심 역할** | **RAG 및 데이터 처리 특화** (사서 역할) | **종합 AI 애플리케이션 구축** (레고 조립 세트) |
| **주요 목적** | 사내 문서/데이터 정제, 청킹, 메타데이터 부여, 벡터 DB 검색 | 다양한 LLM 연동, 에이전트(Agent) 구현, 외부 API 호출, 챗봇 흐름 제어 |
| **언제 쓸까?** | • PDF, Notion, DB 등 **내 데이터를 검색(RAG)**하는 데 집중할 때<br><br>• 데이터를 효율적으로 자르고 정리하는 파이프라인이 필요할 때 | • 챗봇, 웹 브라우징 에이전트, 복잡한 워크플로우를 가진 앱을 만들 때<br><br>• 여러 AI 기능과 외부 서비스들을 사슬처럼 연결할 때 |
| **장 점** | • RAG 구축에 필요한 데이터 로더/인덱싱 기능이 매우 뛰어남<br><br>• 문서 검색 정확도를 높이기 위한 전처리가 간편함 | • 생태계가 매우 크고 지원하는 연동 기능(통합 모듈)이 다양함<br><br>• 복잡한 에이전트 및 로직 제어에 유연함 |
| **단 점** | • 단순 RAG 이외의 복잡한 에이전트 흐름 제어는 상대적으로 제한적 | • 데이터 전처리/인덱싱만 다루기에는 학습 곡선이 다소 높을 수 있음 |

> 💡 **실무 꿀팁**: 데이터 적재 및 검색(RAG) 파이프라인은 **라마인덱스**로 구성하고, 사용자 대화 흐름 및 외부 연동은 **랭체인**으로 가져가는 조합도 자주 쓰입니다.

<summary>📚 AI 모델 양자화(Quantization) & QLoRA</summary>

## 1. 양자화(Quantization)란?

* **정의**: AI 모델의 가중치(Weight)를 표현하는 비트(Bit) 수를 줄여서, **모델의 용량과 메모리(VRAM) 사용량을 대폭 줄이고 구동 속도를 높이는 기술**입니다.
* **필요성**: 32비트 원본 모델은 거대하여 일반 PC나 로컬 환경에서 구동하기 어렵기 때문에, 정밀도를 적절히 낮추어 자원 제약을 극복합니다.

---

## 2. 비트(Bit)별 양자화 단계 및 특징

| 단계 | 포맷 / 명칭 | 특징 및 설명 |
| --- | --- | --- |
| **32bit** | `FP32` (일반)

 | 모델을 처음 학습(Pre-training)할 때 사용하는 기본 고정밀 포맷. 성능은 최고이나 용량이 너무 큼 |
| **16bit** | `FP16 / BF16` (일반적 양자화)

 | 성능 손실이 거의 없으면서 용량을 절반으로 줄여주는 **실무 및 배포의 기본 기준점(Baseline)** |
| **8bit** | `LLM.int(8)` (치환)

 | 16비트 모델을 8비트 정수로 치환하여 VRAM을 절반 수준으로 추가 압축 (`LLM.int()` 등 기법 활용)

 |
| **4bit** | `QLoRA` (극단적 압축)

 | 4비트로 강력하게 압축하여 일반 소비자용 GPU에서도 거대 모델 구동 및 파인튜닝을 가능하게 한 혁신 기술 |
| **1.58 bit** | `1.58 LLM` (BitNet 등)

 | 가중치를 `-1, 0, 1` 세 가지 상태로만 표현하여 복잡한 곱셈 연산을 덧셈 위주로 처리, 전력과 속도를 극대화한 최신 기법

 |
| **1bit** | `Binary Quantization`<br> | 가중치를 `0`과 `1` (또는 `-1`, `+1`) 두 가지로만 표현하는 극한의 이진 양자화 (정보 손실 방어 연구 지속 중)

 |

---

## 3. 미리 양자화된 모델 활용 (Hugging Face 생태계)

* 커뮤니티(예: bartowski 등)에서 이미 용도별로 압축해 둔 모델을 곧바로 활용 가능합니다.
* **GGUF 형식**: 로컬 PC 환경(Ollama, LM Studio 등)에서 CPU와 GPU를 병행해 구동할 때 최적화된 파일 포맷.
* **AWQ / EXL2 형식**: 그래픽카드(GPU) VRAM에 통째로 올려 초고속 추론을 할 때 사용하는 고성능 4비트/8비트 포맷.
* **Qwen 시리즈 등**: 인기 오픈소스 모델들도 위와 같은 양자화 버전이 완벽하게 지원됨.



---

## 4. QLoRA 파인튜닝의 핵심 메커니즘 (양자화 + LoRA)

이미 양자화된 모델을 활용해 일반 PC에서도 나만의 맞춤형 모델을 학습시키는 워크플로우입니다.

1. **양자화된 베이스 모델 준비**:
* 허깅페이스 등에서 이미 4비트 등으로 압축된 베이스 모델을 가져와 메모리 부담을 해소합니다.


2. **모델 본체 동결 (Freezing)**:
* 가져온 거대한 모델의 원본 가중치는 단 1도 수정되지 않도록 100% 꽁꽁 얼려둡니다.


3. **내부 레이어에 어댑터(Adapter) 장착**:
* 모델 외부가 아닌, 내부 핵심 레이어 속에 하얗게 비어 있는 아주 작은 학습용 공간(LoRA 어댑터, 전체의 1% 미만)을 살짝 심어 넣습니다.


4. **효율적인 부분 학습**:
* 커스텀 데이터셋으로 학습을 진행할 때, 얼어 있는 본체는 건드리지 않고 **오직 새로 장착한 어댑터 조각만 쏙쏙 골라서 학습**합니다.


5. **결과물**:
* `[양자화된 베이스 모델 + 커스텀 학습된 어댑터]` 조합이 완성되어 적은 자원으로 완벽한 파인튜닝을 달성할 수 있습니다.

# 🧭 벡터 검색 아키텍처: ANN과 주요 구현 알고리즘 (HNSW, IVF, LSH)

대규모 문서 청크나 임베딩 벡터를 다룰 때, 모든 벡터를 일일이 다 비교하는 방식(Brute-force/완전 탐색)은 데이터가 수만~수백만 개를 넘어가면 감당할 수 없을 정도로 느려집니다. 이를 해결하기 위해 등장한 개념이 바로 **ANN**입니다.

---

## 1. ANN (Approximate Nearest Neighbor, 근사 이웃 탐색) — [상위 개념 / 목표]

* **정의**: 100% 완벽하게 정확한 최단 거리(정답)를 찾는 대신, **아주 미세한 오차(근사치)를 허용하는 대신 탐색 속도를 수십~수백 배 이상 끌어올리겠다**는 대원칙이자 목표입니다.
* **필요성**:
* 챗봇이나 검색 엔진은 밀리초(ms) 단위의 빠른 응답 속도가 생명입니다.
* 1,024차원 같은 고차원 벡터 수십만 개를 실시간으로 완전 탐색하는 것은 연산 부하가 너무 크기 때문에, ANN 알고리즘을 통해 탐색해야 할 대상 후보군을 대폭 압축하여 속도를 확보합니다.



---

## 2. ANN을 구현하는 대표적인 세부 알고리즘들

ANN이라는 큰 목표를 달성하기 위해 데이터의 특성과 인프라 환경에 맞춰 사용하는 대표적인 세부 구현 방식들입니다.

### ① HNSW (Hierarchical Navigable Small World) — [그래프 기반]

* **동작 원리**:
* 데이터를 다층 구조의 그물망(그래프) 형태로 연결합니다.
* 상위 층은 멀리 있는 데이터들을 성글게 연결하여 빠른 대략적 이동을 돕고, 하위 층으로 내려갈수록 촘촘하게 연결되어 정확한 위치를 찾아냅니다. 마치 고속도로와 동네 골목길을 조합한 형태입니다.


* **장점**:
* 현재 존재하는 벡터 검색 알고리즘 중 가장 압도적인 검색 속도와 정확도(Recall)를 자랑합니다.


* **단점**:
* 그래프 구조 전체를 메모리(RAM)에 유지해야 하므로 **메모리(RAM) 사용량이 매우 높습니다.** (메모리 여유가 충분할 때 최우선으로 고려되는 방식입니다.)



### ② IVF (Inverted File Indexing) — [클러스터링 기반]

* **동작 원리**:
* 전체 데이터를 성향이 비슷한 것들끼리 묶어 여러 개의 구역(클러스터, Voronoi Cell 등)으로 미리 쪼개둡니다. (군집화)
* 사용자의 쿼리(질문)가 들어오면 모든 데이터를 뒤지는 것이 아니라, **쿼리와 가장 가까운 몇 개의 구역(Clusters)만 콕 집어서 그 안의 벡터들만 탐색**합니다.


* **주요 파라미터 (`nprobe`)**:
* 몇 개의 구역을 뒤져볼 것인지 결정하는 설정값입니다. `nprobe`를 높이면 정확도는 올라가지만 속도가 느려지고, 낮추면 속도는 빨라지지만 정확도가 떨어집니다.


* **장점**:
* HNSW에 비해 **메모리 소모가 적고, 대규모 데이터셋을 다룰 때 효율적**입니다.


* **단점**:
* 클러스터 경계 부근에 있는 데이터는 놓칠 위험이 있어 HNSW에 비해 정확도(Recall)가 살짝 떨어질 수 있습니다.



### ③ LSH (Locality-Sensitive Hashing) — [해싱 기반]

* **동작 원리**:
* 무작위의 가상 선(Hyperplane)을 그어 공간을 쪼갠 뒤, 서로 비슷한 위치에 있는 데이터들은 동일한 해시 값(버킷/바구니)에 쏙 들어가도록 묶어줍니다.
* 검색할 때는 쿼리가 속한 해시 버킷 내부의 데이터들만 빠르게 꺼내어 비교합니다.


* **장점**:
* 연산 방식이 매우 단순하고 직관적이며 속도가 빠릅니다.


* **단점**:
* 그래프나 클러스터링 방식에 비해 정확도를 높이기 까다로워 현대 고성능 벡터 DB에서는 상대적으로 채택 비중이 줄어드는 추세입니다.

# 📚 RAG (Retrieval-Augmented Generation) & Vector Search Architecture

대규모 문서 기반 챗봇 시스템에서 텍스트가 어떻게 벡터화되고, 어떻게 검색되며, 최종적으로 어떻게 답변이 생성되는지 전체 아키텍처와 역할 분담을 정리한 문서입니다.

---

## 1. 핵심 구성 요소 및 역할 분담

RAG 시스템은 하나의 모델이 모든 것을 다 하는 것이 아니라, 각기 다른 역할을 가진 도구들이 단계별로 협력하는 구조입니다.

### 🤖 1) 임베딩 모델 (Embedding Model) — [좌표 변환기 / 지도 제작자]

* **역할**: 사용자가 입력한 텍스트나 방대한 문서 조각들을 컴퓨터가 이해할 수 있는 숫자 좌표(벡터)로 변환해 주는 번역기입니다.
* **특징**: 데이터를 저장할 때와 검색할 때 **반드시 동일한 임베딩 모델**을 사용하여 동일한 '의미 공간(좌표계)'을 유지해야 합니다.

### 🧭 2) ANN / HNSW (Approximate Nearest Neighbor) — [길찾기 알고리즘 / 탐색 엔진]

* **역할**: 임베딩 모델이 만들어 놓은 거대한 벡터 지도 위에서, "지금 내 위치(질문 벡터)에서 가장 가까운 목적지(문서 벡터)가 어디지?"를 빛의 속도로 계산해 찾아내는 탐색 시스템입니다.
* **특징**: AI 모델이 아니라 수학적/컴퓨터 과학적 **탐색 알고리즘**이며, 실무에서는 `FAISS` 같은 라이브러리를 통해 구현됩니다. (대표 방식: HNSW, IVF 등)

### ✍️ 3) LLM (Large Language Model) — [작가 / 답변 생성기]

* **역할**: 검색 엔진(ANN)이 찾아다 준 사내 규정 문서 조각들과 사용자의 원래 질문을 조합하여, 자연스러운 문장으로 최종 답변을 작성(생성)하는 역할입니다.

---

## 2. RAG 전체 동작 파이프라인

사용자가 질문을 던졌을 때 시스템 내부에서 일어나는 흐름입니다.

```text
[1. 사용자 질문 입력] 
       ↓
[2. 임베딩 모델] ──> 질문을 숫자 좌표(벡터)로 변환
       ↓
[3. ANN / HNSW] ──> 벡터 지도 위에서 가장 가까운 문서 조각을 초고속 탐색
       ↓
[4. 컨텍스트 조합] ──> 질문 + 찾아낸 문서 내용을 하나로 묶음
       ↓
[5. LLM] ──> 문서를 읽고 자연스러운 최종 답변 생성
       ↓
[6. 사용자 전달]

```

| **데이터 파이프라인 (Data Pipeline)** | **[정의]** 원본 데이터의 수집·정제·검증·청킹·적재 단계를 정해진 순서와 규칙에 따라 자동으로 연결해 실행하는 시스템 구조 / **[비유]** 원재료를 넣으면 세척·손질·검수·포장까지 자동으로 이어지는 스마트 공장 컨베이어 벨트 | 각 전처리 단계를 독립된 함수(stage_*)로 만들고, 앞 단계의 출력 문서 목록이 다음 단계의 입력으로 자동 전달되도록 연결해 일괄 실행함 | 사람이 주피터 노트북 셀을 위에서부터 손으로 하나씩 누르는 방식은 실행 순서를 헷갈리거나 자동 정기 실행(야간 배치)을 할 수 없기 때문임 |
| **단계 간 계약 (Stage Contract)** | **[정의]** 파이프라인의 모든 단계 함수가 주고받는 입력·출력 데이터의 형식(스키마)과 상태 기록 방식을 하나로 통일한 규칙 / **[비유]** 공장의 모든 기계가 똑같은 규격으로 주고받는 표준 운반 상자(Doc) | 모든 단계 함수가 동일한 문서 객체(Doc) 리스트를 입력받아 처리 이력(history)과 상태(status)만 갱신한 뒤 같은 형식의 리스트로 반환함 | 단계마다 출력 모양이 제각각이면 순서를 바꾸거나 중간에 건수를 세고 저장(체크포인트)하는 공통 실행기를 만들 수 없음 |
| **멱등성 (Idempotency)** | **[정의]** 동일한 입력과 설정으로 작업을 한 번 실행하든 여러 번 반복 실행하든 최종 저장소의 상태가 항상 똑같이 유지되는 성질 / **[비유]** 엘리베이터 5층 버튼(한 번 누르든 열 번 연타하든 결과는 똑같이 5층 도착) | 문서와 청크의 ID를 현재 시각이나 난수가 아닌 파일 경로와 내용 해시로 고정하여, 재실행 시 기존 항목 위에 그대로 덮어쓰기함 | 네트워크 오류나 스케줄러 재시도로 파이프라인을 두 번 돌렸을 때 벡터DB에 똑같은 문서가 2배, 3배로 중복해서 쌓이는 사고를 막기 위해 필수적임 |
| **결정적 식별자 (Deterministic ID)** | **[정의]** 난수나 현재 시각을 쓰지 않고 오직 데이터의 내용과 경로만을 재료로 계산해, 입력이 같으면 언제나 100% 동일한 값이 나오는 고유 ID / **[비유]** 접수 순서대로 뽑는 대기번호표가 아니라 사람마다 평생 고정된 주민등록번호 | 파일 상대 경로와 정규화된 본문 텍스트를 합쳐 SHA-256 해시 함수에 통과시킨 앞 12~16자리 문자열을 doc_id와 chunk_id로 사용함 | 실행할 때마다 ID가 새로 발급되면 벡터DB가 어제 넣은 문서와 오늘 넣은 문서를 다른 문서로 착각해 중복 저장하기 때문임 |
| **덮어쓰기 (Upsert)** | **[정의]** 데이터베이스에 데이터를 적재할 때 같은 ID가 이미 존재하면 내용을 갱신(Update)하고, 없으면 새로 삽입(Insert)하는 결합 연산 / **[비유]** 주소록에 같은 이름이 있으면 전화번호만 고쳐 적고, 없으면 새 줄에 추가하기 | 결정적 식별자(point_id)를 기준으로 벡터DB에 적재 요청을 보내어, 이미 들어 있는 청크는 중복 생성 없이 최신 상태로 덮어씀 | 기존 데이터가 있는지 먼저 조회한 뒤 수정할지 추가할지 분기하는 복잡한 코드 없이 단 한 번의 요청으로 멱등성을 보장해 줌 |
| **체크포인트 (Checkpoint)** | **[정의]** 파이프라인의 각 단계가 끝날 때마다 중간 산출물을 디스크에 파일로 저장해 두어 장애 발생 시 중단된 단계부터 다시 시작(Resume)할 수 있게 하는 장치 / **[비유]** 긴 게임에서 스테이지마다 기록해 두는 중간 세이브 파일 | 각 단계가 끝날 때마다 ./stage/ 폴더에 JSON 파일을 저장하고, 오류 발생 후 재실행 시 start_from=“실패한_단계”로 직전 세이브 파일을 불러와 이어 달림 | 10단계 중 8단계에서 멈췄을 때 시간이 오래 걸리는 1~7단계(문서 수천 건 파싱 등)를 처음부터 다시 실행하는 시간과 비용 낭비를 막아 줌 |
| **데이터 리니지 (Data Lineage)** | **[정의]** 최종 산출물(청크)이 어느 원본 문서의 어떤 버전에서 시작해 어떤 전처리 단계와 설정·패키지 버전을 거쳐 만들어졌는지 기록한 데이터 계보 / **[비유]** 마트 정육 코너의 소고기 이력추적 바코드(농장·도축일·가공장 즉시 조회) | 실행 전체 기록(실행 리니지), 문서별 처리 이력(데이터 리니지), 청크 내부의 8개 출처 메타데이터(청크 리니지) 3계층으로 나누어 저장함 | 챗봇이 오답을 냈을 때 전체 파이프라인을 다시 돌려보지 않고도 문제가 된 청크 하나만 보고 3분 안에 원인(구버전 문서, 파서 오류 등)을 역추적하기 위해 필요함 |
| **증분 처리 (Incremental Processing)** | **[정의]** 매번 전체 문서를 처음부터 다시 처리(Full Refresh)하지 않고, 직전 실행 이후 추가·수정·삭제된 변경분(Delta)만 골라 처리하는 방식 / **[비유]** 집 전체 대청소 대신 어제 이후로 어질러진 방만 골라 치우기 | 이전 실행의 파일 해시 목록(스냅샷)과 현재 폴더 목록을 비교해 바뀐 문서만 파싱·청킹하고, 안 바뀐 문서는 이전 청크를 그대로 재사용함 | 사내 문서가 수만 건으로 늘어나 전체 처리 시간이 배치 주기(예: 1시간)를 넘어설 때 실행 시간과 연산 비용을 획기적으로 줄여 줌 |
| **스냅샷 조정 (Reconciliation)** | **[정의]** 직전 실행 스냅샷과 현재 원본 목록을 대조해, 원본에서 삭제되었거나 수정된 문서의 구버전 잔류 청크(stale chunks)를 인덱스에서 찾아 지우는 동기화 작업 / **[비유]** 어제 출석부와 오늘 출석부를 나란히 대조해 전학 간 학생의 사물함을 비우는 작업 | 이전 스냅샷에는 있었으나 현재 스냅샷에 없는 문서 ID(삭제 또는 수정으로 해시 변경)를 찾아 그 문서에서 파생된 기존 청크 ID들을 벡터DB에서 삭제함 | 삭제된 문서는 현재 폴더에 아무 흔적이 남지 않으므로, 스냅샷 대조로 지워주지 않으면 폐기된 구버전 규정이 벡터DB에 유령처럼 남아 오답을 유발함 |
| **검증 게이트 (Validation Gate)** | **[정의]** 파이프라인 단계 사이에서 데이터 건수·통과율·검색 품질(Golden Set)을 자동 검사해 기준 미달 시 실행을 즉시 중단(Hard Gate)하거나 경고(Soft Gate)를 남기는 방어 장치 / **[비유]** 불량품이나 빈 상자가 감지되면 컨베이어 벨트를 즉시 멈추는 비상 정지 스위치 | 산출물이 0건이거나 대표 평가 질의(Golden Set)의 1위 정답률(hit@1)이 떨어지면 예외를 발생시켜 운영 인덱스 반영을 차단함 | 공유 폴더 연결이 끊겨 문서가 0건 수집되어도 파이썬은 에러 없이 ’성공’으로 끝나며 기존 정상 인덱스를 빈 인덱스로 덮어쓰는 무음 장애를 막아 줌 |

| **완전 탐색 (Brute-Force / Exact k-NN)** | **[정의]** 질의 벡터와 저장된 모든 문서 벡터 사이의 유사도를 처음부터 끝까지 전수 계산해 가장 가까운 상위 k개를 찾는 방식 / **[비유]** 도서관의 모든 책을 1번부터 끝번까지 한 권도 빠짐없이 다 펼쳐보고 찾는 방식 | 넘파이(NumPy) 행렬 곱셈으로 전체 벡터와 질의 벡터의 내적 점수를 전부 계산한 뒤 점수 순으로 정렬함 | 하나도 놓치지 않는 100% 정답(기준선)을 보장하지만, 벡터가 수백만 개이고 동시 검색 요청이 몰리면 CPU 연산량이 폭발해 느려짐 |
| **근사 최근접 이웃 (ANN)** | **[정의]** 100% 정확한 정답을 조금 양보하는 대신, 탐색 범위를 대폭 줄여 아주 빠른 속도로 가장 비슷할 법한 상위 k개 벡터를 찾는 검색 알고리즘 계열 / **[비유]** 도서관 전체를 뒤지는 대신 분야별 이정표를 따라가며 유력한 책장 몇 곳만 빠르게 살펴보는 방식 | 사전에 벡터들 사이의 지도(그래프나 클러스터 인덱스)를 만들어 두고, 검색 시 지도를 따라 일부 후보만 비교함 | 대규모 벡터 환경에서 검색 시간을 수십~수백 분의 1로 줄여 수십 명이 동시에 검색해도 즉각 응답할 수 있게 해 줌 |
| **재현율 (Recall@k)과 미검출률 (Miss Rate)** | **[정의]** 완전 탐색이 찾은 진짜 상위 k개 정답 중 ANN 검색이 실제로 찾아낸 비율(Recall@k)과 놓친 비율(Miss Rate = 1 - Recall@k) / **[비유]** 모범 답안 10개 중에서 우리 검색기가 몇 개를 맞히고 몇 개를 빠뜨렸는지 매기는 채점표 | 동일한 질의에 대해 넘파이 완전 탐색 상위 10개와 벡터DB 검색 상위 10개의 교집합 개수를 세어 비율을 계산함 | ANN 속도 최적화나 메모리 압축을 적용했을 때 검색 품질이 얼마나 떨어졌는지 숫자로 정확히 감시하기 위해 필수적임 |
| **HNSW (계층적 작은 세상 그래프)** | **[정의]** 벡터들을 다층 네트워크 그래프로 연결해, 위층의 성긴 급행 경로에서 아래층의 촘촘한 완행 경로로 내려가며 가까운 이웃을 찾는 인덱스 구조 / **[비유]** KTX 고속철도로 큰 도시까지 단숨에 이동한 뒤 지하철과 도보로 정확한 목적지 번지수를 찾아가는 경로 탐색 | 상위 층에는 소수의 대표 벡터만 멀리 연결하고 최하위 층에는 모든 벡터를 이웃끼리 촘촘히 연결해 위에서 아래로 좁혀 내려감 | 현재 전용 벡터DB(Qdrant, Milvus, Weaviate)와 pgvector에서 검색 속도와 정확도 균형이 가장 뛰어나 표준으로 쓰이는 인덱스임 |
| **HNSW 파라미터 (m · ef_construct · ef)** | **[정의]** 그래프 구축 시 벡터당 연결할 이웃 수(m), 구축 시 후보 탐색 폭(ef_construct), 검색 시 후보 탐색 폭(ef)을 조절하는 3대 설정값 / **[비유]** 도시마다 뚫어 놓을 도로 개수(m)와 지도 제작 정밀도(ef_construct), 그리고 길 찾기 할 때 둘러볼 교차로 개수(ef) | m과 ef_construct는 인덱스를 처음 만들 때 정하고, ef(hnsw_ef)는 검색 요청을 보낼 때마다 실시간으로 바꿔가며 속도와 정확도를 조절함 | 기본값만 쓰면 우리 데이터에서 정확도가 부족하거나 반대로 불필요하게 메모리를 낭비하므로, 직접 곡선을 그려 최적의 운영값을 찾아야 함 |
| **페이로드 인덱스 (Payload Index)** | **[정의]** 벡터에 붙어 있는 메타데이터(부서명, 보안 등급, 작성 연도 등) 필드에 대해 별도로 만들어 두는 고속 색인표 / **[비유]** 책 본문 내용과 별개로 출판 연도별·부서별로 즉시 추려낼 수 있게 붙인 색깔 견출지 | 특정 메타데이터 값을 가진 벡터 ID 목록을 미리 정리해 두어, 조건 필터가 들어왔을 때 전체 벡터를 뒤지지 않고 대상만 즉시 골라냄 | 사내 검색은 늘 부서·권한 필터와 함께 실행되는데, 페이로드 인덱스가 없으면 필터링 구간에서 검색 속도가 몇 배로 느려지거나 정답을 놓침 |
| **스칼라 양자화 (SQ8)와 이진 양자화 (BQ)** | **[정의]** 32비트 실수(4바이트) 벡터 숫자를 8비트 정수(1바이트, SQ8)나 1비트 부호(양수/음수, BQ)로 줄여 메모리 사용량을 1/4 ~ 1/32로 압축하는 기법 / **[비유]** 초고화질 원본 사진을 일반 화질(SQ8)이나 흑백 실루엣(BQ)으로 용량을 줄여 메모리에 많이 담아 두는 기술 | 각 차원의 소수점 숫자를 256단계 정수(SQ8)로 반올림하거나 0 기준 부호 비트(BQ)로 변환해 RAM에 상주시킴 | 고가의 서버 RAM 용량을 75%~97%까지 아껴 같은 서버에서 수배~수십 배 더 많은 문서를 검색할 수 있게 해 줌 |
| **오버샘플링과 재점수화 (Oversampling & Rescore)** | **[정의]** 압축된 양자화 벡터로 필요한 개수(k)보다 몇 배수(오버샘플링)로 후보를 넉넉히 뽑은 뒤, 원본 정밀 벡터로 점수를 다시 계산(재점수화)해 최종 k개를 확정하는 기법 / **[비유]** 흑백 요약본으로 유력 후보 40명을 빠르게 추린 뒤, 그 40명만 고화질 원본 서류를 꺼내 최종 합격자 10명을 뽑는 2단계 심사 | 예를 들어 상위 10개가 필요할 때 오버샘플링 4배수를 주면 압축 벡터로 40개를 초고속 추출한 후 디스크의 FP32 원본 벡터로 40개만 재계산함 | 이진 양자화(BQ)처럼 압축률이 높은 기법을 쓸 때 발생하는 정확도 하락을 거의 원본 수준으로 회복시켜 주는 핵심 보정 장치임 |
| **컬렉션 별칭 (Collection Alias)** | **[정의]** 실제 물리 컬렉션 이름(예: docs_v1, docs_v2) 앞에 붙여 애플리케이션이 고정해서 바라보게 하는 논리적 대표 이름표(예: prod_docs) / **[비유]** 회사가 건물을 이사해도 고객이 거는 대표 전화번호(별칭)는 그대로 두고 착신 연결만 새 건물로 바꾸는 방식 | 새 설정의 컬렉션(docs_v2)을 백그라운드에서 다 만든 뒤, 별칭(prod_docs)이 가리키는 대상만 0.01초 만에 docs_v2로 전환함 | 임베딩 모델을 교체하거나 HNSW 설정을 바꿔 전체 재인덱싱을 할 때, 서비스 중단(다운타임)이 전혀 없이 안전하게 새 인덱스로 배포하기 위해 사용함 |
| **스냅샷과 평균 복구 시간 (Snapshot & MTTR)** | **[정의]** 특정 시점의 벡터 컬렉션 전체 상태를 파일 하나로 통째 박제한 백업본(Snapshot)과, 장애 발생 시점부터 정상 서비스 복구까지 걸리는 평균 시간(MTTR) / **[비유]** 컴퓨터 시스템 복원 지점 파일(스냅샷)과 고장 났을 때 복원 버튼을 눌러 정상 작동하기까지 걸리는 스톱워치 시간(MTTR) | 운영 컬렉션의 스냅샷 압축 파일을 생성해 별도 저장소에 보관하고, 컬렉션 유실 장애 시 스냅샷을 업로드해 복원한 뒤 별칭을 재연결함 | 벡터 그래프 인덱스는 처음부터 다시 임베딩·인덱싱하려면 몇 시간이 걸리므로, 이미 완성된 인덱스를 스냅샷으로 남겨 수십 초 안에 복구하기 위해 필수적임 |

| 용어 | 개념 (실제 정의 + 비유) | 동작방식 | 왜 필요한가 |
| --- | --- | --- | --- |
| **폐쇄망 (Air-gapped Network)** | **[정의]** 기밀 유출과 외부 해킹을 원천 차단하기 위해 외부 인터넷망과 물리적·논리적으로 완전히 단절시켜 운영하는 내부 전용 네트워크 환경 / **[비유]** 외부와 전화선·도로가 모두 끊긴 보안 연구소 건물 | 외부 인터넷으로 나가는 모든 통신 경로가 차단되어 있어, 필요한 소프트웨어와 모델 파일은 보안 심의를 거쳐 저장 매체나 망연계 시스템으로만 반입함 | 금융·국방·공공기관 및 기업의 핵심 영업비밀 문서를 다루는 Private LLM 시스템이 외부 클라우드로 데이터를 한 줄도 내보내지 않기 위한 필수 환경임 |
| **전이 의존성 (Transitive Dependency)** | **[정의]** 내가 설치하려는 패키지가 내부적으로 동작하기 위해 연쇄적으로 필요로 하는 하위 패키지들과 그 하위 패키지들의 의존성 전체 / **[비유]** 자동차 한 대를 반입하려면 눈에 보이는 차체뿐 아니라 그 안에 들어가는 부품 수백 개가 함께 따라와야 하는 구조 | 예를 들어 패키지 2개만 지정해 다운로드해도 실제로는 그 2개가 부르는 하위 패키지 수십 개가 함께 수집됨 | 폐쇄망에 최상위 패키지 파일 2개만 들고 들어가면 하위 부품 패키지가 없어 설치가 즉시 실패하므로 전이 의존성 전체를 빠짐없이 묶어가야 함 |
| **휠 번들과 잠금 파일 (Wheel Bundle & Lockfile)** | **[정의]** 컴파일이 완료된 파이썬 설치 파일(.whl) 모음과, 설치할 모든 패키지의 정확한 버전 번호를 `==`로 고정해 기록한 명세서(`requirements-lock.txt`) / **[비유]** 현장에서 조립만 하면 되는 완제품 부품 상자(.whl)와 부품 번호를 1mm 오차 없이 적어 둔 설계 명세서(Lockfile) | 인터넷이 되는 외부 PC에서 `pip download --only-binary=:all:`로 `.whl` 파일들을 받고, 폐쇄망 안에서는 `--no-index --find-links` 옵션으로 로컬 폴더에서만 설치함 | 폐쇄망 서버에는 C/C++ 컴파일러가 없는 경우가 많아 소스 파일(.tar.gz)은 설치에 실패하며, 버전을 고정하지 않으면 패키지 간 충돌이 발생하기 때문임 |
| **모델 스냅샷과 레지스트리 (Snapshot & Registry)** | **[정의]** 원격 저장소(Hugging Face)의 모델 가중치·토크나이저·설정 파일 전체를 특정 커밋 버전(`revision`) 기준으로 로컬 폴더에 그대로 복제한 사본과 그 관리 대장(`model_registry.json`) / **[비유]** 온라인 스트리밍 대신 영화 원본 파일과 자막 설정 파일을 통째로 외장하드에 담아 목록표와 함께 반입하는 것 | `snapshot_download(local_dir=...)`로 심볼릭 링크 없이 실제 파일을 내려받고, 코드에서는 모델 이름 대신 로컬 폴더 경로만 읽어 모델을 로드함 | 코드에 모델 이름을 적어 두면 라이브러리가 인터넷으로 최신 버전을 확인하려다 죽고, 특수 토큰 설정 파일이 빠지면 모델이 엉뚱한 기호를 출력하기 때문임 |
| **마이크로서비스와 로컬호스트 격리 (127.0.0.1)** | **[정의]** 임베딩·생성·벡터검색을 독립된 서버 프로세스로 분리해 띄우되, 오직 자기 컴퓨터 내부(`127.0.0.1`)에서만 접속할 수 있게 네트워크 문을 잠그는 설계 / **[비유]** 주방·창고·계산대를 별도 방으로 분리하되, 외부 손님은 절대 주방에 직접 못 들어가고 카운터(오케스트레이터)를 통해서만 주문하게 막는 구조 | 각 서버를 `--host 127.0.0.1`로 기동하여 외부 네트워크 카드(`0.0.0.0`)로의 직접 노출을 차단하고 오케스트레이터만 내부 포트로 호출함 | 한 모델이 멈춰도 다른 서비스가 함께 죽지 않게 격리하고, 사내망의 허가받지 않은 사용자가 인증 없이 모델 서버를 직접 호출하는 보안 사고를 막음 |
| **텔레메트리 (Telemetry / Phone-Home)** | **[정의]** 오픈소스 라이브러리나 데이터베이스가 실행될 때 개발사 서버로 사용 통계, 오류 보고, 최신 버전 확인 신호를 몰래 자동 전송하는 기능 / **[비유]** 가전제품이 켜질 때마다 본사 서버에 “저 방금 켜졌어요”라고 자동 안부 전화를 거는 기능 | 라이브러리 임포트나 서버 기동 시 백그라운드 스레드가 외부 도메인(예: huggingface.co, 버전 체크 서버 등)으로 HTTP 연결을 시도함 | 폐쇄망에서는 이러한 암묵적 외부 통신 시도가 보안 관제 시스템에 ‘외부 유출 시도’ 경보로 잡히거나 타임아웃 대기로 시스템 기동을 지연시키므로 반드시 꺼야 함 |
| **소켓 가드 (Socket Guard / Egress 후킹)** | **[정의]** 파이썬의 네트워크 출구 함수(`socket.connect`, `getaddrinfo`)를 코드로 가로채어, 허용된 내부 주소(`127.0.0.1`) 외의 모든 외부 통신 시도를 차단하고 범인(호출 코드 위치)을 기록하는 감시 장치 / **[비유]** 건물 출입구에 보안 검색대를 세워 내부 직원 외에 밖으로 나가려는 모든 우편물을 즉시 압수하고 발송 부서를 장부에 적어 두는 장치 | 도메인 이름을 IP로 바꾸는 DNS 조회 단계와 실제 연결 단계를 모두 감싸서, 외부 주소면 즉시 `PermissionError`로 막고 호출 스택(Traceback)을 로그에 남김 | 보안 감사에서 “우리 코드는 밖으로 안 나갑니다”라는 말뿐인 주장 대신 **“외부 연결 시도를 100% 차단했고 어느 라이브러리가 시도했는지 채증했다”는 증거**를 제시하기 위해 필요함 |
| **성능 저하 모드 (Graceful Degradation / Fallback)** | **[정의]** 시스템의 일부 구성 요소(예: LLM 서버)에 장애가 발생했을 때 전체 서비스를 중단하는 대신, 살아 있는 구성 요소만으로 한 단계 낮춘 결과를 제공하는 장애 대응 기법 / **[비유]** 엘리베이터가 고장 나도 건물을 폐쇄하지 않고 비상계단 안내판을 켜서 방문객이 목적지 층까지 갈 수 있게 돕는 방식 | LLM 서버가 죽으면 벡터DB가 찾은 규정 조항 원문을 그대로 보여주고(`degraded_generate`), 임베딩 서버가 죽으면 로컬 키워드 검색으로 전환(`degraded_search`)함 | 사내 챗봇에서 LLM 서버가 재기동되는 수 분 동안 사용자가 에러 화면 대신 최소한 찾고자 하는 사내 규정 조항 원문이라도 즉시 확인할 수 있게 가동률을 지켜 줌 |
| **슈퍼바이저와 지수 백오프 (Supervisor & Exponential Backoff)** | **[정의]** 백그라운드에서 각 서버의 건강 상태(`/health`)를 주기적으로 점검해 죽은 서버를 자동 재기동하되, 연속 실패 시 재시도 대기 시간을 2초·4초·8초처럼 배수로 늘리는 관리 장치 / **[비유]** 쓰러진 기계를 자동으로 다시 켜주는 관리인이되, 과열로 자꾸 꺼지면 식을 시간을 점점 길게 주며 재시도하는 안전장치 | 주기적으로 `/health`에 요청을 보내 응답이 없으면 프로세스를 다시 띄우고, 재기동 횟수가 늘어날수록 `min(2 ** restarts, 30)`초만큼 대기 후 재시도함 | 새벽에 서버가 죽었을 때 사람이 출근해서 알아차릴 때까지 기다리지 않고 수십 초 안에 자동 복구(MTTR 단축)하면서도 무한 재기동 루프로 서버가 뻗는 것을 막아 줌 |
| **추론 잠금과 LRU 임베딩 캐시 (Lock & LRU Cache)** | **[정의]** 단일 GPU에 동시 추론 요청이 몰려 메모리가 터지는 것을 막기 위해 한 번에 하나씩 순서대로 통과시키는 잠금 장치(`Lock`)와, 최근 자주 물어본 질문의 임베딩 벡터를 메모리에 저장해 재사용하는 기법(`LRU Cache`) / **[비유]** 1인용 탈의실 앞에 번호표 줄 세우기(`Lock`)와 자주 묻는 질문의 정답지를 책상 위에 미리 꺼내 두기(`LRU Cache`) | `threading.Lock`으로 GPU 모델 호출 구간을 보호하고, `@lru_cache`로 동일 텍스트가 들어오면 모델 연산 없이 저장된 벡터를 0.001초 만에 반환함 | 단일 GPU 환경에서 동시 접속자가 몰릴 때 서버가 죽는 현상을 방지하고, 반복되는 사내 단골 질문의 임베딩 연산 시간을 0에 가깝게 줄여 줌 |

# 📖 머신러닝 & 딥러닝 핵심 용어 통합 사전
---

## 1. 데이터 전처리 (Data Preprocessing)

* **특징 / 피처 (Feature, $X$):** 모델 예측의 입력으로 사용되는 데이터의 속성이나 변수 (예: 집값 예측의 '평수', '방 개수').
* **라벨 / 타겟 (Label / Target, $Y$):** 모델이 예측해서 맞춰야 하는 실제 정답 데이터.
* **결측치 (Missing Value):** 데이터셋에서 누락되거나 비어있는 값 (예: `NaN`, `Null`).
* **이상치 (Outlier):** 일반적인 데이터 범주에서 크게 벗어난 비정상적인 수치.
* **원-핫 인코딩 (One-Hot Encoding):** 범주형 문자 데이터를 `[1, 0, 0]`과 같이 0과 1의 이진 벡터 형태(범주형 데이터)로 변환하는 작업.
* **정규화 (Normalization):** 서로 다른 피처의 스케일(범위)을 $0 \sim 1$ 등의 동일한 구간으로 맞추어 학습 효율을 높이는 과정.

---

## 2. 학습 데이터 단위 및 횟수 (Data & Epoch)

* **Train Data Set (학습 데이터셋):** 모델을 학습시키기 위해 사용하는 전체 데이터의 집합.
* **배치 사이즈 / 미니 배치 (Batch Size / Mini Batch):** 모델이 한 번의 학습에서 묶어서 가져오는 데이터의 개수/규모.
* **스텝 / 이터레이션 (Step / Iteration):** 배치(Batch) 하나를 학습하고 가중치를 1회 업데이트하는 단위 횟수.
* **에포크 (Epoch):** 전체 학습 데이터셋을 처음부터 끝까지 한 번 모두 학습시킨 상태 (1 Epoch = 전체 데이터 완독).
  * *예시:* 전체 데이터가 100개이고 Batch Size가 10이면 $\rightarrow$ 10 Iteration = 1 Epoch.

---

## 3. 신경망 구조 및 연산 (Neural Network Architecture)

* **노드 / 뉴런 (Node / Neuron):** 인공신경망을 구성하는 가장 기본적인 계산 단위.
* **입력층 (Input Layer):** 모델로 입력되는 데이터($x_1, x_2$ 등)를 받아들이는 첫 번째 레이어.
* **은닉층 (Hidden Layer):** 입력층과 출력층 사이에 위치하며, 데이터의 복잡한 특징과 패턴을 추출하는 레이어.
* **출력층 (Output Layer):** 최종 예측값($\hat{y}$)을 계산하여 출력하는 마지막 레이어.
* **완전 연결 층 (Dense Layer / Fully Connected Layer):** 이전 레이어의 모든 노드가 다음 레이어의 모든 노드와 1:1로 전부 연결된 레이어 구조.
* **다층 퍼셉트론 (Multi-Layer Perceptron, MLP):** 하나 이상의 은닉층을 쌓아 만든 가장 대표적인 기본 딥러닝 인공신경망 구조.
* **가중치 (Weight, $w$):** 입력 값이 결과에 미치는 중요도나 영향력을 조절하는 학습 파라미터 (기울기).
* **편향 (Bias, $b$):** 노드가 얼마나 쉽게 활성화(발화)될지를 결정하여 그래프 전체의 위치를 이동시키는 상숫값 (절편, $y = wx + b$).
* **활성화 함수 (Activation Function):** 입력 값에 비선형성(Non-linearity)을 부여하여 신경망이 복잡한 패턴을 학습할 수 있게 만들어주는 함수 (예: ReLU, Sigmoid, Softmax 등).

---

## 4. 순전파 및 역전파 (Forward & Backward Pass)

* **순전파 (Feed Forward / Forward Pass):** 입력 데이터가 `입력층` $\rightarrow$ `은닉층` $\rightarrow$ `출력층` 방향으로 이동하며 최종 예측값($\hat{y}$)을 계산하는 과정.
* **역전파 (Backward Pass / Backpropagation):** 예측 오차(Loss)를 줄이기 위해, 손실을 출력층에서 입력층 반대 방향으로 거꾸로 전달하면서 각 가중치($w$)를 얼마큼 수정해야 할지 계산하는 알고리즘.
* **체인 룰 / 연쇄 법칙 (Chain Rule):** 역전파 연산 시 미분의 연쇄적인 성질을 이용해 미분값(기울기)을 순차적으로 구해내는 수학적 원리.

---

## 5. 성능 평가, 오차 및 지표 (Loss & Metric)

* **예측값 (Prediction, $\hat{y}$):** 모델이 입력 데이터($x$)를 받아 예측해 낸 결과값.
* **오차 (Error):** 실제 정답($y$)과 모델 예측값($\hat{y}$)의 차이 ($\hat{y} - y$).
* **손실 함수 (Loss Function):** 모델 학습 시 오차의 크기를 측정하는 컴퓨터 최적화용 수학 공식 (작을수록 좋으며, 미분 가능해야 함).
  * **MSE (Mean Squared Error, 평균 제곱 오차):** 예측값과 실제값 차이를 제곱하여 평균을 낸 회귀 기본 손실 함수.
  * **Cross-Entropy:** 분류 문제에서 예측 확률 분포와 실제 정답 간의 차이를 계산하는 손실 함수.
* **평가지표 (Metric):** 학습 완료 후 사람이 직관적으로 성능을 판단하기 위한 평가 기준 (예: Accuracy, Precision, Recall).
  * **RMSE (Root Mean Squared Error):** MSE에 루트를 씌워 실제 데이터와 동일한 단위 스케일로 정렬한 평가 지표.
  * **MAE (Mean Absolute Error):** 오차의 절댓값을 평균 낸 지표로, 이상치(Outlier)의 영향에 상대적으로 강함.
  * **정확도 (Accuracy):** 전체 예측 데이터 중 정답을 맞춘 데이터 비율.

---

## 6. 학습 상태 및 최적화 (Optimization & Regularization)

* **과적합 (Overfitting):** 모델이 훈련 데이터의 잡음(Noise)까지 너무 과도하게 외워서, 새로운 테스트 데이터에서는 성능이 떨어지는 현상.
* **과소적합 (Underfitting):** 모델의 표현력이 부족하거나 학습이 덜 되어, 훈련 데이터조차 충분히 학습하지 못하는 현상.
* **최적화 (Optimization):** Loss 수치를 최소화할 수 있도록 모델의 파라미터(가중치 $w$)를 조절해 나가는 과정.
* **기울기 / 그라디언트 (Gradient):** 손실 함수 그래프에서 Loss가 가장 가파르게 변하는 방향과 변화율.
* **학습률 (Learning Rate, LR):** 최적화 과정에서 가중치를 한 번 수정할 때 이동하는 수치 범위(발걸음의 폭).
* **경사 하강법 (Gradient Descent):** 기울기를 계산해 그 반대 방향으로 조금씩 가중치를 이동시켜 손실(Loss)의 최솟값을 찾아가는 최적화 알고리즘.
* **확률적 경사 하강법 (SGD):** 무작위로 뽑은 미니 배치(Mini-batch) 데이터를 이용하여 빠르게 가중치를 업데이트하는 경사 하강법.
* **옵티마이저 (Optimizer):** 경사 하강법을 발전시켜 효율적으로 가중치를 업데이트하는 최적화 도구 (예: SGD, Momentum, Adam, RMSProp 등).
* **규제 (Regularization):** 과적합을 방지하기 위해 가중치의 크기에 패널티를 부여하여 과도한 학습을 억제하는 기법 (예: L1 Lasso, L2 Ridge, Dropout 등).
* **배치 정규화 (Batch Normalization):** 레이어 사이에서 미니 배치 단위로 데이터의 분포를 정돈하여 학습을 빠르고 안정적으로 도와주는 기술.
* **조기 종료 (Early Stopping):** 검증 손실(Validation Loss)이 더 이상 감소하지 않고 다시 증가하기 시작하는 시점(과적합 시작점)에서 학습을 자동으로 중단하는 기술.

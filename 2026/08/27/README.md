### ⚖️ Regularization vs Normalization

한국어로 둘 다 '정규화'로 번역되는 경우가 많아 헷갈리기 쉬운 **Regularization**과 **Normalization**의 핵심 차이점 비교입니다.

| 구분 | Regularization (규제 / 정칙화) | Normalization (정규화) |
| :--- | :--- | :--- |
| **주요 목적** | **과적합(Overfitting) 방지** 및 모델 일반화 성능 향상 | **데이터 스케일(범위) 통일** 및 학습 안정화·속도 향상 |
| **적용 대상** | **모델의 가중치($W$)** 또는 모델 구조 자체 | **입력 데이터(Features)** 또는 **레이어의 활성화값(Activation)** |
| **핵심 원리** | 가중치($W$)가 너무 커지지 않도록 손실함수에 패널티를 부여하거나 노드를 생략함 | 데이터 분포의 범위를 일정한 구간(예: $0 \sim 1$ 또는 평균 0, 표준편차 1)으로 맞춤 |
| **주요 기법** | L1 규제 (Lasso), L2 규제 (Ridge), Dropout, Early Stopping | Min-Max Scaling, Standard Scaling, Batch Normalization |
| **대표 비유** | 모델이 너무 암기하지 못하도록 **족쇄/제약**을 채우는 것 | 선수들의 **체급(스케일)**을 공평하게 맞춰주는 것 |


**regularization의 목적은 처음 보는 데이터(validation/test)에서도 잘 맞히는 것**  
train loss는 약간 올라갈 수 있지만, 대신 validation/test loss가 낮아지는 것을 노립니다.

---

💡 **참고 지식: 과적합(Overfitting)은 왜/언제 생기는가?**

과적합은 모델이 데이터의 **일반적인 패턴**을 학습하는 것이 아니라, 훈련 데이터의 **사소한 특징(노이즈)까지 통째로 외워버릴 때** 발생합니다.

---

### **1. 과적합이 주로 발생하는 4가지 상황**

* 📉 **데이터 문제:** 학습 데이터가 부족하거나 품질이 낮을 때
* ⚙️ **모델 구조 문제:** 모델이 데이터에 비해 너무 복잡할 때 *(파라미터 수 과다)*
* ⏳ **학습량 문제:** 같은 데이터를 필요 이상으로 너무 오래 학습할 때 *(Epoch 과다)*
* 🧹 **피처 문제:** 불확실하거나 노이즈(잡음)가 많은 Feature가 섞여 있을 때

---

### **2. 과적합 진단 방법 (Learning Curve)**

과적합 여부를 확인하는 가장 대표적인 방법은 **Train Loss**와 **Validation Loss**를 하나의 그래프에 그려 비교해 보는 것입니다.

* **정상 학습:** Train Loss와 Validation Loss가 함께 원만하게 감소함
* **과적합 발생:** Train Loss는 계속 줄어들지만, Validation Loss가 어느 시점부터 정체되거나 다시 상승함 (두 곡선의 격차가 벌어짐)

---

### 🔄 Epoch, Batch Size, Iteration 개념 비교

| 개념 | 영문명 | 핵심 의미 | 쉬운 비유 (100페이지 문제집 기준) |
| :--- | :--- | :--- | :--- |
| **에포크** | **Epoch** | 전체 데이터를 처음부터 끝까지 **1회 학습**하는 단위 | 문제집 100페이지를 **1회독 완료** |
| **배치 크기** | **Batch Size** | 한 번의 묶음 학습에 사용하는 **데이터 개수** | 한 번에 풀 문제 분량 (**10페이지씩** 묶음) |
| **이러레이션 / 스텝** | **Iteration / Step** | 1 Epoch를 마치기 위해 **배치를 제출/학습한 횟수** | 100페이지를 10페이지씩 풀었을 때 **총 제출 횟수 (10회)** |

> 💡 **수식 관계:**  
> $\text{1 Epoch} = \text{Batch Size} \times \text{Iteration (Steps)}$

# 🎯 머신러닝 규제(Regularization): L1 (Lasso) vs L2 (Ridge)

선형 회귀(Linear Regression) 모델의 과대적합(Overfitting)을 방지하고 일반화 성능을 높이기 위해 사용하는 **L1 규제(Lasso)**와 **L2 규제(Ridge)**의 개념, 차이점, 사용 시기를 정리한 가이드입니다.

---

## 📌 1. 규제(Regularization)란 왜 필요할까?

기본 **선형 회귀(Linear Regression)**는 주어진 데이터의 오차(Loss)만을 최소화하는 방향으로 학습합니다. 
그러나 데이터에 노이즈가 많거나 특징(Feature/열)의 개수가 너무 많으면, 모델이 학습 데이터에 지나치게 맞춰져 **과대적합(Overfitting)**이 발생합니다.

* **손실 함수 (Basic Loss Function):**
  $$\text{Loss} = \text{MSE (Mean Squared Error)}$$

규제(Regularization)는 손실 함수에 **가중치(Weight/기울기)에 대한 패널티(Penalty) 항**을 추가하여 가중치가 너무 커지지 않도록 억제하는 기법입니다.

---

## ⚖️ 2. L1 Regularization (Lasso) vs L2 Regularization (Ridge)

| 구분 | **L1 Regularization (Lasso)** | **L2 Regularization (Ridge)** |
| :--- | :--- | :--- |
| **수학적 패널티** | 가중치 **절댓값의 합** ($\vert{}w\vert{}$) | 가중치 **제곱의 합** ($w^2$) |
| **손실 함수** | $\text{MSE} + \alpha \sum \vert{}w_i\vert{}$ | $\text{MSE} + \alpha \sum w_i^2$ |
| **가중치 변화** | 불필요한 특징의 가중치를 **정확히 0**으로 만듦 | 가중치를 **0에 가깝게 완만하게 줄임** (0은 안 됨) |
| **주요 효과** | **특징 선택 (Feature Selection)** / 모델 단순화 | **과대적합 방지** / 가중치 안정화 |
| **주요 사용 상황** | **특징(열/Column)의 개수가 매우 많을 때** | 모든 특징이 어느 정도 의미를 가질 때 |
| **주의할 점** | $\alpha$가 너무 크면 중요 변수도 0이 되어 **가로선($y=b$)**이 됨 | 특징 개수를 줄이지 않으므로 메모리/계산 유지 |

---

## 🔍 3. 심층 분석: 작동 원리 및 특징

### 🥊 L1 규제 (Lasso - Least Absolute Shrinkage and Selection Operator)
> **"필요 없는 열(Column)은 싹둑 잘라내어 지워버리는 칼"**

* **핵심 특징:** 
  * 중요도가 낮은 특징의 가중치(기울기)를 **완전히 `0`**으로 만듭니다.
  * 100개의 특징 중 유의미한 10개만 남기고 나머지는 제거하는 **Feature Selection** 효과가 있습니다.
* **가로선 문제 발생 원인:**
  * 만약 특징이 단 1개만 있는 상태에서 L1 규제 강도($\alpha$)를 너무 높이면, 하나뿐인 특징의 기울기마저 `0`이 되어 $y = 0 \cdot x + b \Rightarrow y = b$ 형태의 **평평한 가로선**을 그려버립니다.

### 🛡️ L2 규제 (Ridge)
> **"모든 특징을 살려두되, 영향력을 부드럽게 낮추는 정지 마찰력"**

* **핵심 특징:**
  * 모든 가중치를 **0에 가깝게 균일하게 축소**하지만, 절대 **`0`으로 만들지는 않습니다.**
  * 다중공선성(Multi-collinearity, 특징들 간의 강한 상관관계)이 존재할 때 매우 안정적인 성능을 보입니다.
  * 그래프상에서 대각선의 기울기가 완만해질 뿐, 데이터의 전반적인 경향선(대각선)을 계속 유지합니다.

---

## 🛡️ 과적합 방지 기법 (Regularization) 비교

| 항목 | **L1 정규화 (Lasso)** | **L2 정규화 (Ridge / Weight Decay)** | **드롭아웃 (Dropout)** |
| :--- | :--- | :--- | :--- |
| **적용 위치** | Loss 계산식 (`loss + l1_lambda * l1_norm`) | Optimizer 설정 (`weight_decay=1e-4`) | Model 클래스 내 레이어 (`nn.Dropout`) |
| **제어 대상** | 가중치(Weight)의 절댓값 | 가중치(Weight)의 제곱 | 신경망 노드(Neuron) 간 연결 |
| **핵심 동작** | 중요도가 낮은 가중치를 **완전히 `0`으로 삭제** | 모든 가중치를 **전반적으로 작고 얌전하게 축소** | 학습 시 무작위로 **일부 노드를 끔 (OFF)** |
| **실무 사용 빈도** | 🔴 **낮음** (특수한 경우에만 사용) | 🟢 **매우 높음** (사실상 기본 적용) | 🟢 **매우 높음** (딥러닝 필수 기법) |
| **주요 사용 상황** | • 중요한 변수(Feature)만 선별하고 싶을 때<br>• 입력 데이터 종류가 너무 많고 듬성할 때 | • 모델의 급격한 가중치 변화를 막고 안정화할 때<br>• 기본적이고 전반적인 오버피팅을 방지할 때 | • 신경망이 깊고 복잡할 때 (FC Layer, CNN 등)<br>• 특정 노드 편중 현상(동조)을 방지할 때 |
| **장점** | 불필요한 입력값을 완전히 제거하여 모델 경량화 | 가중치를 균일하게 관리하여 모델 안정성 향상 | 앙상블(Ensemble) 효과를 제공하여 실전 성능 대폭 증가 |
| **단점** | 미분 불가능한 지점이 있어 학습 제어가 까다로움 | 가중치를 `0`으로 만들지는 못해 변수 선별 불가 | 학습 시간이 약간 늘어나며 평가 시 모드 전환 필수 |

---

### 📌 Summary

- **L2 Regularization + Dropout** 조합이 현대 PyTorch 실무에서 **가장 흔하게 사용되는 표준 조합**입니다.
- **L1 Regularization**은 PyTorch 옵티마이저에서 기본 옵션을 제공하지 않을 정도로 단독 사용 빈도는 낮지만, **특징 선택(Feature Selection)**이 필수적인 특수 환경에서 조합하여 사용됩니다.

## 💻 4. Python (Scikit-Learn) 실습 코드

```python
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression, Lasso, Ridge

# 1. 데이터 준비 (Pandas [[ ]]를 사용하여 처음부터 2차원 DataFrame으로 추출)
X = iris_df.loc[iris_df['species'] == 'virginica', ['petal length (cm)']] # Shape: (50, 1) - 2D
Y = iris_df.loc[iris_df['species'] == 'virginica', 'sepal length (cm)']   # Shape: (50,) - 1D

# 2. 기본 선형 회귀 (Linear Regression)
linear = LinearRegression()
linear.fit(X, Y)

# 3. L1 규제 회귀 (Lasso) - alpha 조절 필수
lasso = Lasso(alpha=0.01) # alpha가 너무 크면 기울기가 0이 되어 가로선이 됨
lasso.fit(X, Y)

# 4. L2 규제 회귀 (Ridge)
ridge = Ridge(alpha=1.0)
ridge.fit(X, Y)

print(f"Linear 기울기: {linear.coef_[0]:.4f}")
print(f"Lasso  기울기: {lasso.coef_[0]:.4f}")
print(f"Ridge  기울기: {ridge.coef_[0]:.4f}")
```

## 💡 PyTorch 핵심 개념 & FAQ 정리

### 1. 차원 조작 3대장 (`reshape`, `unsqueeze`, `squeeze`)
* **`reshape`**: 데이터 순서를 유지하면서 차원의 모양(형태)을 **전면 재배치**
* **`unsqueeze`**: 지정한 위치에 **크기가 `1`인 차원 추가** (포장지 씌우기)
* **`squeeze`**: 크기가 **`1`인 불필요한 차원 제거** (포장지 벗기기)

---

### 2. 브로드캐스팅(Broadcasting) 동작 원리
Shape가 다른 텐서끼리 연산할 때 파이토치가 자동으로 형태를 맞춰주는 기능입니다.

* **차원 수 맞추기**: 1차원 `(3,)`과 2차원 `(4, 1)`을 연산하면, `(3,)` 앞에 크기 `1`인 차원을 자동 추가하여 `(1, 3)`으로 해석합니다.
  > ⚠️ 이때 추가되는 `1`은 데이터값 `1`이 아니라 **"1줄짜리 차원의 틀"**을 의미합니다. (알맹이 데이터 개수는 동일)
* **크기 확장하기**: 부족한 축(크기 `1`)을 상대방 크기만큼 복사하여 늘립니다.
  * `(4, 1)` $\rightarrow$ `(4, 3)`
  * `(1, 3)` $\rightarrow$ `(4, 3)`
  * **결과 shape:** `torch.Size([4, 3])`

### 3. 핵심 Q&A
* **Q. 딥러닝에서 기본 `dtype`은?**
  * `torch.float32` (연속적인 미분 및 가중치 업데이트를 위해 실수형 사용)
* **Q. "Expected all tensors to be on the same device" 에러 해결법은?**
  * 연산하는 텐서들의 위치를 하나로 통일 (`.to("cuda")` 또는 `.to("cpu")`)
* **Q. `reshape` vs `permute` 차이는?**
  * `reshape`: 데이터 순서를 유지하며 형태 변환
  * `permute`: 축(Axis)의 순서 자체를 교환
* **Q. `cat` vs `stack` 차이는?**
  * `cat`: 기존 차원에 이어붙이기 (차원 유지)
  * `stack`: 새로운 차원을 만들어 위로 쌓기 (차원 +1 증가)

## 1. 학습 스위치 및 미분 제어

---

## 2. 역전파 및 미분 실행

| 명령어 / 구문 | 설명 | 주요 사용 상황 |
| :--- | :--- | :--- |
| `y.backward()` | $y$에 연결된 연산 그래프를 역방향으로 추적하여 **미분을 실행(버튼 역할)**합니다. | Loss(오차) 계산 직후 역전파 수행 시 |
| `x.grad` | `backward()` 실행 결과, $x$ 위치에 쌓인 **최종 미분값(기울기)이 저장**되는 변수입니다. | 가중치 업데이트 상태 확인할 때 |

> 💡 **주의 사항 (Loss와 스칼라)**
> `y.backward()`는 $y$가 **단 하나의 숫자(0D 텐서 = 스칼라 = Loss)**일 때만 바로 동작합니다. 
> 여러 값이 섞인 텐서인 경우 `.sum()`이나 `.mean()`으로 하나의 대표 오차 점수로 뭉개준 뒤 호출해야 합니다.

---

## 3. 그래디언트 누적(Accumulation)과 초기화 (`zero_grad()`) ⚠️ [중요]

### 1) 그래디언트 누적 현상
PyTorch의 `backward()`는 미분값을 **덮어쓰지 않고 기존 `grad` 변수에 더하는(누적) 방식**으로 동작합니다.
```python
y1 = x ** 2
y1.backward() # x.grad -> 6.0

y2 = x ** 2
y2.backward() # x.grad -> 12.0 (6.0 + 6.0 누적됨!)
```

### 2) 왜 매 회차(Batch/Epoch)마다 초기화해야 하는가?
* **문제점:** 이전 데이터(예: 1월 데이터)의 오답노트(Gradient)가 남아있으면, 다음 데이터(예: 2월 데이터) 학습 시 미분값이 2배, 3배로 짬뽕되어 가중치가 이상한 방향으로 고쳐집니다.
* **해결법:** 새로운 데이터를 학습하기 직전에 반드시 `optimizer.zero_grad()` 또는 `x.grad.zero_()`를 실행해 미분값을 `0`으로 리셋해야 합니다.

## 4. 학습 진행 시 메모리와 지식의 변화

배치/에폭 단위로 데이터가 계속 넘어갈 때 메모리와 모델 상태의 핵심 변화입니다.

| 구분 | 항목 | 학습 진행 시 상태 |
| :--- | :--- | :--- |
| **사라지는 것 (초기화)** | Loss, Gradient(미분값), 연산 그래프 | **`zero_grad()`로 초기화**하여 다음 연산을 위한 메모리 확보 |
| **남아있는 것 (기억)** | **모델 가중치 ($W, b$)** | **이전 데이터 학습 결과가 반영되어 유지됨** (지식의 단련) |

> 💡 **핵심 요약**  
> * **Loss & Gradient:** 가중치를 한 번 고치기 위해 흘리는 **'땀방울 / 임시 오답노트'** (고치고 나면 씻어냄)  
> * **Weight ($W$):** 운동을 통해 단련된 **'모델의 근육 / 실제 지식'** (다음 학습으로 계속 이어짐)


## 💡 활성화 함수 (Activation Functions)

신경망(Neural Network)에 **비선형성(Non-linearity)**을 부여하여 모델이 복잡한 데이터 패턴을 학습할 수 있도록 돕는 핵심 함수입니다.

---

### 1. ReLU (Rectified Linear Unit)
> **중간 층(은닉층)의 기본 선택지**

- **특징**: 입력값이 0 이하이면 `0`, 0 이상이면 `입력값 그대로` 출력합니다. $\max(0, x)$
- **출력 범위**: $[0, \infty)$
- **장점**: 연산이 매우 단순하여 학습 속도가 빠르고, 딥러닝의 기울기 소실(Gradient Vanishing) 문제를 해결해 줍니다.
- **주요 용도**: 대부분의 신경망 은닉층(Hidden Layer) 기본 활성화 함수.

---

### 2. Sigmoid
> **이진 분류(Binary Classification)의 출력층 전용**

- **특징**: 어떤 값이 들어오든 모든 출력값을 `0과 1 사이`로 압축하는 S자 형태의 곡선 함수입니다.
- **출력 범위**: $(0, 1)$
- **장점**: 출력값을 **확률(Probability)** 형태(예: 0.85 = 85% 확률)로 직관적으로 해석할 수 있습니다.
- **주요 용도**: 두 개의 클래스를 구분하는 이진 분류 문제의 **최종 출력층(Output Layer)**.

---

### 3. Tanh (Hyperbolic Tangent)
> **음수/양수 방향성이 중요한 은닉층 및 시계열 모델**

- **특징**: Sigmoid와 유사한 S자 곡선 형태이지만, 출력 범위를 `-1과 1 사이`로 압축합니다.
- **출력 범위**: $(-1, 1)$
- **장점**: 출력값의 평균이 `0`에 위치(Zero-centered)하므로 Sigmoid보다 학습 효율이 좋습니다.
- **주요 용도**: 은닉층 및 시계열/순환 신경망(RNN, LSTM 등).

---

### 📊 한눈에 비교하기

| 활성화 함수 | 연산 공식 | 출력 범위 | 추천 사용 위치 |
| :--- | :--- | :---: | :--- |
| **`nn.ReLU()`** | $\max(0, x)$ | $0 \le y < \infty$ | **은닉층 (기본값)** |
| **`nn.Sigmoid()`** | $\frac{1}{1 + e^{-x}}$ | $0 < y < 1$ | **출력층 (이진 분류)** |
| **`nn.Tanh()`** | $\frac{e^x - e^{-x}}{e^x + e^{-x}}$ | $-1 < y < 1$ | **은닉층 / RNN** |

## 🛠️ PyTorch `torch.nn` 핵심 도구 및 자동화 원리

PyTorch는 복잡한 신경망의 파라미터(가중치 $W$, 편향 $b$) 및 학습 과정을 자동으로 관리해 줍니다.

---

### 1. `torch.nn` 주요 구성 요소를 통한 파이프라인 비교

| 분류 | 직접 수동 구현 (Numpy / Basic Tensor) | `torch.nn` 자동화 도구 | 설명 |
| :--- | :--- | :--- | :--- |
| **파라미터 생성** | `W = torch.tensor(..., requires_grad=True)`<br>`b = torch.tensor(..., requires_grad=True)` | **`nn.Linear(in, out)`** | 가중치($W$)와 편향($b$)을 **자동 생성 및 관리** |
| **순전파 연산** | `y_pred = w * x + b` | **`model(x)`** | 등록된 $W, b$를 사용해 $W \cdot x + b$ 연산 수행 |
| **오차(손실) 계산**| `loss = ((y_pred - y) ** 2).mean()` | **`loss_fn = nn.MSELoss()`** | 예측값(`pred`)과 실제값(`target`)의 오차 계산 |
| **파라미터 갱신** | `w -= lr * w.grad`<br>`b -= lr * b.grad` | **`optimizer.step()`** | **모든 $W$와 $b$를 한 번에 갱신** |
| **기울기 초기화** | `w.grad.zero_()`<br>`b.grad.zero_()` | **`optimizer.zero_grad()`** | **모든 파라미터의 누적 기울기를 0으로 초기화** |

---

### 2. `optimizer.step()`의 내부 동작 원리

`optim.Adam(model.parameters(), lr=0.001)`과 같이 `model.parameters()`를 옵티마이저에 전달하면, 옵티마이저는 모델 내의 **가중치($W$)와 편향($b$) 목록 전체**를 관리하게 됩니다.

따라서 단 한 줄의 `optimizer.step()` 실행만으로 다음과 같은 작업이 자동으로 수행됩니다:

1. **가중치($W$) 업데이트**: $W \leftarrow W - \text{lr} \times W.\text{grad}$
2. **편향($b$) 업데이트**: $b \leftarrow b - \text{lr} \times b.\text{grad}$

> 💡 **핵심 요약:** 레이어가 수십~수백 개로 늘어나더라도 `optimizer.step()`과 `optimizer.zero_grad()` 한 줄로 모델 전체의 $W$와 $b$를 일괄 처리할 수 있습니다.

---

### 3. `nn.Sequential`을 통한 신경망 조립 및 차원 맞물림

`nn.Sequential`은 여러 레이어와 활성화 함수를 순서대로 연결하는 컨베이어 벨트 역할을 합니다.

```python
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(784, 256),  # 입력 784개 -> 출력 256개
    nn.ReLU(),            # 은닉층 활성화 함수
    nn.Linear(256, 10)    # 입력 256개 -> 출력 10개 (이전 층의 출력 차원과 반드시 일치해야 함)
)
```
## 🏗️ `nn.Module` 클래스 상속 패턴

PyTorch에서 커스텀 모델을 만들 때는 기본적으로 `nn.Module` 클래스를 상속받아 정의합니다. 딱 두 가지 핵심 규칙만 기억하면 됩니다.

---

### ✌️ 핵심 2가지 규칙

1. **`__init__()` 메서드**: 모델에서 사용할 **부품(레이어, 활성화 함수 등)을 미리 선언**합니다.
   - `super().__init__()`을 첫 줄에 반드시 호출해야 부모 클래스의 기능이 올바르게 초기화됩니다.
2. **`forward()` 메서드**: 입력 데이터($x$)가 선언된 **부품들을 통과하는 순서(연산 흐름)**를 작성합니다.
   - 모델을 호출할 때(`model(x)`) 내부적으로 이 `forward` 함수가 자동으로 실행됩니다.

## 📦 커스텀 Dataset 만들기 (`torch.utils.data.Dataset`)

PyTorch에서 자신만의 데이터를 다룰 때는 `Dataset` 클래스를 상속받아 구현합니다. 필수 필수 메서드 두 가지만 구현하면 됩니다.

---

### ✌️ 핵심 필수 구현 메서드 2가지

1. **`__len__()`**: 데이터셋의 **전체 데이터 개수(총 길이)**를 반환합니다.
   - `len(dataset)`을 호출할 때 작동합니다.
2. **`__getitem__(idx)`**: `idx`번째 인덱스에 해당하는 **단일 데이터 1개(입력 $x$, 정답 $y$)**를 어떻게 꺼내서 반환할지 정의합니다.
   - `dataset[idx]` 형태로 접근할 때 호출됩니다.

## 🎨 transforms: 데이터 변환

`transform`은 Dataset에서 **데이터를 꺼낼 때마다 적용되는 전처리 함수**입니다. 입문 단계에서는 아래 두 가지 핵심 전처리를 확실히 알면 됩니다.

---

### 1. 핵심 전처리 두 가지

* **`ToImage` + `ToDtype(float32, scale=True)`**: 이미지를 `float32` 텐서로 바꾸고 `0 ~ 1`로 스케일링
* **`Normalize(mean, std)`**: 평균을 빼고 표준편차로 나눠 분포를 표준화. 학습을 안정시킴

---

### 2. 스케일링(Scaling) vs 표준화(Standardization) 비교

| 구분 | 스케일링 (Scaling) | 표준화 / 노멀라이징 (Standardization) |
| :--- | :--- | :--- |
| **적용 함수** | `ToDtype(..., scale=True)` | `Normalize(mean, std)` |
| **변환 후 범위** | `0.0 ~ 1.0` | `-1.0 ~ 1.0` (평균 = 0) |
| **동작 원리** | 픽셀 값($0\sim255$)의 비율만 유지하며 축소 | 원래 값에서 평균을 빼고 표준편차로 나눔 |
| **학습 효과** | 데이터 타입을 텐서로 변환 및 정규화 | 데이터 중심을 `0`으로 이동(Zero-centered)시켜 경사하강법 안정화 |

---

## 📦 DataLoader 사용하기

`Dataset`은 1개의 샘플(`(1, 28, 28)`)을 꺼내주지만, **`DataLoader`를 통과하면 지정한 배치 크기만큼 묶어서 4차원 텐서(`(64, 1, 28, 28)`)** 형태로 반환합니다.

---

### 1. 핵심 옵션 세 가지

* **`batch_size`**: 한 번에 몇 개씩 묶을 것인가 (보통 `32 ~ 256` 사용)
* **`shuffle`**: 매 에폭(Epoch)마다 데이터 순서를 섞을 것인가 
  * **학습용(Train): `True`** (데이터 순서를 외우는 과적합 방지)
  * **평가용(Test/Val): `False`** (순서가 성능 평가에 영향을 주지 않도록 고정)
* **`num_workers`**: 데이터를 미리 읽어 두는 병렬 프로세스 개수 (Colab 환경에서는 보통 `2` 설정)

---

### 📌 학습 루프 5단계 상세 설명

| 단계 | 명칭 | 실행 코드 | 역할 및 설명 |
| :---: | :--- | :--- | :--- |
| **1** | **Forward (순전파)** | `pred = model(x)` | 입력 데이터 `x`를 모델에 통과시켜 **예측값(`pred`)**을 구합니다. |
| **2** | **Loss (손실 계산)** | `loss = loss_fn(pred, y)` | 모델의 예측값과 실제 정답(`y`)을 비교하여 **얼마나 틀렸는지(오차 수치)**를 계산합니다. |
| **3** | **Zero_grad (기울기 초기화)** | `optimizer.zero_grad()` | **이전 배치에서 계산되어 남아있던 기울기(Gradient)를 `0`으로 비워줍니다.** |
| **4** | **Backward (역전파)** | `loss.backward()` | 손실(Loss)을 바탕으로 각 가중치(Parameter)에 대한 **기울기(미분값 $\frac{\partial L}{\partial w}$)를 계산**합니다. |
| **5** | **Step (파라미터 업데이트)** | `optimizer.step()` | 계산된 기울기를 바탕으로 **가중치를 실제로 수정(경사하강법 적용)**합니다. |

---

### 💡 Core Concept: 왜 `optimizer.zero_grad()`가 필수일까요?

1. **PyTorch의 기울기 누적 방식 (`+=`)**
   * PyTorch는 `loss.backward()`를 실행할 때 기존 기울기를 덮어쓰지 않고 **누적(Accumulate)**하는 기본 특성을 가집니다.
2. **초기화를 안 할 경우 생기는 문제**
   * 이전 배치에서 계산했던 기울기 잔여물이 그대로 남아있는 상태에서 현재 배치의 기울기가 더해져 오차가 엉뚱하게 오버슈팅되고 학습이 완전히 망가지게 됩니다.
3. **결론**
   * 첫 번째 배치에서는 이전 잔여물이 없지만, 두 번째 배치부터는 이전 값의 중첩 현상이 발생하므로 **매 배치 시작 전(또는 역전파 전) 기울기를 청소해 주는 과정이 필수**입니다.

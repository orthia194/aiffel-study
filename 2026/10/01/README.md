### 1. 챗봇 vs AI 에이전트 비교

| 구분 | 챗봇 (Chatbot) | AI 에이전트 (AI Agent) |
| --- | --- | --- |
| **기본 역할** | 질문에 대한 텍스트 답변 생성 및 요약 | **지정된 목표(Goal) 완수를 위한 자율적 행동** |
| **작동 방식** | **수동적 1문 1답** (질문 $\rightarrow$ 답변) | **자율적 연속 실행** (목표 $\rightarrow$ 계획 $\rightarrow$ 실행 $\rightarrow$ 평가) |
| **외부 도구** | 제한적 (내부 지식 / RAG 검색 위주) | **필수적** (API, 웹 브라우저, DB, 코드 실행기, 계산기 등) |
| **오류 대응** | 사람이 직접 수정 지시 및 재질문 필요 | **Self-Reflection** (결과 확인 후 스스로 다시 시도) |
| **비유** | 친절한 **'지식 백과/자문가'** | 목표만 주면 일 끝내고 보고하는 **'유능한 비서'** |

### 2. 싱글홉 vs 멀티홉 추론

RAG나 QA 시스템에서 정답을 도출하기 위해 **필요한 지식 단계를 몇 번(Hop) 거쳐야 하는가**에 따른 분류입니다.

* **싱글홉 (Single-Hop):**
* 단일 문서/문단만으로 정답을 바로 도출할 수 있는 단순 사실 확인 질문.
* *예시:* "삼성전자의 2023년 영업이익은?" $\rightarrow$ 사업보고서 1개로 해결.


* **멀티홉 (Multi-Hop):**
* A 정보를 찾은 뒤 그 결과를 바탕으로 B 정보를 다시 찾아 연결(Bridge)해야 답을 내는 복합 추론 질문.
* *예시:* "영화 '인셉션' 감독의 고향에서 가장 유명한 음식은?"
* *단계:* [인셉션 감독: 크리스토퍼 놀란] $\rightarrow$ [고향: 영국 런던] $\rightarrow$ [대표 음식: 피시 앤 칩스] (3 Hops)



---

### 3. 두 개념의 연결점 (Agentic RAG의 필요성)

* **기존 RAG의 한계:** 1차 단발성 벡터 검색만 수행하는 기존 RAG 챗봇은 멀티홉 질문이 들어왔을 때 필요한 여러 문서를 한 번에 검색해오지 못해 추론 실패율이 높습니다.
* **AI 에이전트의 해결 방식:** AI 에이전트는 멀티홉 질문을 스스로 하위 단계로 쪼갠 뒤, [1차 검색] $\rightarrow$ [결과 분석 및 판단] $\rightarrow$ [2차 검색어 재생성 및 검색] $\rightarrow$ [종합]의 루프를 자율적으로 순환하며 복잡한 문제를 해결합니다.

---

```
[단순 질문 / 단순 검색] ───> 기존 RAG 챗봇으로 해결 가능 (Single-Hop)
[복합 질문 / 다단계 실행] ──> AI 에이전트 (Agentic RAG) 필수 (Multi-Hop)

```

### 📌 AI Agent vs Agentic AI 핵심 정리

두 용어는 언뜻 비슷해 보이지만, '단순 자동화 도구'와 '고도화된 자율 지능 패러다임'이라는 명확한 수준 차이를 갖습니다.

```
[ AI Agent ]   : 정의된 규칙과 범위 내에서 정해진 일을 수행하는 "단일 실행 도구"
[ Agentic AI ] : 스스로 목표를 쪼개고 환경 변화에 맞춰 판단하는 "자율 행동 지능"

```

---

### 📊 상세 비교표

| 구분 | AI Agent (1세대 / 제한적 에이전트) | Agentic AI (고도화된 자율형 AI) |
| :--- | :--- | :--- |
| **개념 정의** | 특정 작업(Task)을 대행하기 위해 만들어진 개체/프로그램 | 스스로 판단하고 적응하는 **자율적 행동 특성 및 파이프라인** |
| **의사결정** | 사람이 미리 정의한 규칙(Rule)과 지침에 따름 | 자율적이고 환경 변화에 맞춰 적응적으로 판단 |
| **목표 설정** | 사람이 부여한 명확하고 고정된 목표 수행 | 거대한 목표 아래 **하위 목표(Sub-goal)를 스스로 세분화** |
| **복잡성** | 비교적 간단하고 정형화된 작업 중심 | 높은 복잡성, 동적이고 비정형적인 문제 해결 |
| **작동 환경** | 변수가 적고 정적이거나 예측 가능한 환경 | 변수가 많고 동적이며 예측 불가능한 환경 |
| **의사소통** | 작업 중심적이며 직접적인 인터랙션 | 상황과 맥락(Context)을 능동적으로 인식 |

### 💡 머릿속에 '개념만' 알고 있으면 좋은 핵심 패턴 4가지



1. **Conditional Routing (조건부 라우팅):**

* 질문 의도나 유형에 따라 다른 검색기/LLM 경로로 분기하는 필수 기본 패턴입니다.


2. **Supervisor (관리자형):**

* 중앙 에이전트가 하위 에이전트들에게 일을 배분하고 조율하는 멀티 에이전트의 대표적 구조입니다.


3. **Self-Reflection (자기 검토형):**

* 앞서 다룬 환각 체크, RAGAS 기반 결과 검수 등 스스로 결과를 개선하는 필수 자아성찰 패턴입니다.


4. **Human in the Loop (사람 개입형):**

* 중요한 결제, 이메일 발송, 고위험 DB 수정 전 최종 승인을 사람에게 받는 실무 필수 패턴입니다.

## 🧩 Agent Architecture Design Patterns

본 프로젝트 및 에이전트 시스템 설계 시 참조하는 대표적인 워크플로우 설계 패턴입니다.

| 패턴명 (Pattern) | 한국어명 | 핵심 특징 | 주요 용도 |
| :--- | :--- | :--- | :--- |
| **Sequential Agent** | 순차 실행 | 단일 에이전트 기반 기본 패턴 | 단순 업무 자동화, 기본 QA |
| **Conditional Routing Agent** | 조건부 라우팅 | 입력 의도에 따라 다른 처리 경로 선택 | 의도 분류 기반 멀티태스킹 |
| **Hierarchical Planning Agent** | 계층형 계획 | 거대한 작업을 하위 작업으로 자율 분해 | 프로젝트 관리, 복합 문제 해결 |
| **Sequential Handoff Pattern** | 순차 협업 | 전문가 에이전트 간 순차적 작업 바통 터치 | 연구 ➔ 분석 ➔ 작성 ➔ 검토 파이프라인 |
| **Parallel Processing Pattern** | 병렬 처리 | 여러 작업 동시 수행 후 결과 통합 | 다중 소스 정보 수집 및 요약 |
| **Debate / Discussion Pattern** | 토론형 | 에이전트 간 교차 검증 및 토론 | 의사결정 지원, 창작 아이디어 도출 |
| **Supervisor Pattern** | 관리자형 | 중앙 관리자가 전체 작업 분배 및 조율 | 복합 업무 관리 시스템 |
| **Human in the Loop** | 사람 개입형 | 중요한 의사결정 시 인간 승인 단계 포함 | 고위험 업무, 최종 결제/발송 프로세스 |
| **Memory-Enhanced Agent** | 기억 강화형 | 과거 대화 이력 및 학습 내용 저장/활용 | 개인화 비서, 장기 학습 시스템 |
| **Self-Reflection Agent** | 자기 검토형 | 자신의 실행 결과를 자체 평가 및 재작성 | 고품질 결과물 생성 (Hallucination 제어) |

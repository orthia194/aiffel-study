2. 난이도 제어 합성 & 문법 강제 디코딩

① 확률 파라미터 기반 난이도 제어 (make_minutes)

단순한 텍스트 생성이 아니라, LLM이 자주 틀리는 4대 취약점을 수학적 확률로 주입하여 난이도를 정밀 제어합니다.

  - missing_owner (0.0 ➔ 0.5): "담당자 미정"을 주어, 참석자 명단에서 아무나 골라 적는 인명 환각을 유도.
  - conditional (0.0 ➔ 0.4): "4월 중 (예산 확정 후)" 같은 조건부 기한을 주어 날짜 날조를 유도.
  - mixed (False ➔ True): "추진 확정"과 "다음 회의로 이월"을 섞어 결정 사항 vs 논의 사항 분류 실패를 유도.
  - items (2개 ➔ 5개): 문맥을 길게 하여 뒤쪽 안건의 누락을 유도.

② FORMAT_SPEC vs GUIDED_JSON_SCHEMA

  - FORMAT_SPEC (사람용 마크다운): ## 회의 개요, ## 결정 사항 등 최종 보고서 양식의 거푸집.
  - GUIDED_JSON_SCHEMA (기계용 JSON): vLLM/OpenAI 엔진의 **Guided Decoding(문법 강제)**을
    이용해, 모델이 토큰을 생성할 때 스키마를 벗어나는 단어는 물리적으로 입을 막아버림(Logit Masking). ➔ JSON 문법
    에러율 0.0% 달성!

③ 지시문 다양성 증강 (INSTRUCTION_VARIANTS)

"정리하세요", "재작성하세요", "옮겨주세요" 등 4가지 변주를 주어 모델이 특정 명령어 말투 하나에만 과적합되지 않도록 사전 훈련.

3. 캐스케이드 필터 & 소형 AI 판사의 한계

① 2중 캐스케이드 필터링 (비용 최적화)

"비싼 LLM 판사를 돌리기 전에, 싸고 빠른 0.001초 파이썬 규칙으로 먼저 쳐낸다!"

1.  filter_format (형식): 4개 섹션 누락, 담당/기한 누락 ➔ 13건 광속 컷!
2.  filter_fact (사실/환각):
      - invented = out_people - src_people: 원문에 없는 유령 인명 색출.
      - len(n) >= 2: 목차 번호(1., 2.)는 허용하고, 진짜 날짜/통계 숫자 환각만 골라내는 실무 디테일.
3.  find_duplicates (중복): 고유명사를 P(사람), N(숫자)으로 마스킹한 뒤
    MinHashLSH(threshold=0.92)를 돌려 뻔한 복붙 템플릿 문장을 제거.

② 소형(3B) 모델 채점관의 치명적 한계 (The "Yes-Man" Bias)

  - 실험 결과: Llama 3B에게 판정을 맡겼더니 불량 적발률 0%, 자기 편애도 +0%가 나옴.
  - 충격적인 진실: 공정한 것이 아니라, 프롬프트 예시(1. 아니오, 2. 아니오)를 기계적으로 복사하며 **모든 시험지에 무조건 100점
    도장을 찍어버린 '태업(무능) 판사'**였음!
  - 실무 교훈: 생성(Generator)은 3B 소형 모델로 빠르게 돌리더라도, 검수관(Judge)은 반드시 상위 대형 모델(70B /
    GPT-4o)을 쓰거나 엄격한 파이썬 규칙(gold_verdict)을 써야 함.

4. 생존자 편향(물수능)과 자가 치유 재조정(Rebalance)

① "쉬운 쪽으로 기운다 (Easy Skew / 생존자 편향)"

  - 엄격하게 필터링을 거쳤더니:
      - 쉬움(Easy): 실수할 게 없으니 100% 통과 (13/13)
      - 보통(Normal): 절반 탈락 54.5% 통과 (12/22)
      - 어려움(Hard): 3분의 1 탈락 66.7% 통과 (6/9)
  - ➔ 결과적으로 살아남은 데이터셋에서 쉬운 문제 비중이 30%에서 42%로 폭증하는 '물수능 현상' 발생!

② 쉬운 문제를 0%로 다 빼버리면 안 되는 이유 ("어른들의 뇌" 역설)

"어른들에게 유치원생 퀴즈를 주면 온갖 의심과 가정을 하다가 틀리는 것과 같다."

  - 어려운 킬러 문제만 편식한 AI는 **과잉 복잡화(Over-complication / 의심병)**에 걸림.
  - 단순한 10분짜리 일상 회의록을 던져줘도 "왜 미정이 없지? 왜 결론 안 난 게 없지?" 하면서 억지로 없는 문제를 지어내는 환각 발생.
  - 쉬운 문제(30%)는 모델이 멘탈을 유지하고 기본기를 잡게 해주는 '무게추(Anchor)' 역할을 함!

③ rebalance 함수의 자가 치유 메커니즘

need = {d: int(target_total * r) for d, r in target_dist.items()}

1.  다운샘플링 (초과분 컷): 넘쳐나는 Easy(13개)는 목표치 9개만 슬라이싱(pool[:9])하고 남는 4개는 과감히 버림.
2.  표적 오버샘플링 (부족분 보충): 부족한 Normal(12개)만 콕 집어서 딱 3번 추가 생성하여 15개로 보충.
3.  ➔ 최종적으로 황금비율 [쉬움 30% : 보통 50% : 어려움 20%]을 단 0.1% 오차 없이 완벽 복원!

5. RAG 검색 왕복 검사 & 거절(Refusal) 백신

① 검색 왕복 검사 (Round-Trip Test)

내가 합성한 질문으로 검색기(TF-IDF/임베딩)를 돌렸을 때, 질문을 만든 원본 청크를 상위 3위 안에 찾아오는지 검증:

  - 날짜 포함 (97%): "3월 18일 협력사 계약 회의..." ➔ 족집게 적중. (우수 데이터)
  - 날짜 없음 (59%): "협력사 계약 회의..." ➔ 8월 협력사 계약 회의와 충돌하여 엉뚱한 회의록 적발!
  - 막연한 질문 (0%): "결론 안 난 안건 뭐야?" ➔ 단서 부족으로 100% 엉뚱한 회의록 검색.
  - ➔ 검색기를 통과하지 못하는 모호한 질문은 RAG 데이터셋에서 자동 탈락시킴.

② '답변 불가(Refusal)' 부정 샘플 (거짓말 방지 백신)

  - LLM은 모르는 걸 물어봐도 어떻게든 아는 척 거짓말을 지어냄.
  - 원문에 없는 가짜 주제("해외 법인 설립 예산")를 일부러 질문으로 던지고, **"원문에 명시되어 있지 않아 확인할 수 없습니다"**라고
    정직하게 거절하는 샘플을 의도적으로 주입하여 모델의 사기 본능(?)을 원천 차단.

6. 통계적 품질 보증(QA) & 인간 검수(HITL)

① 표본 크기 계산 (sample_size)

  - 10만 개 데이터를 전수 검사하는 것은 불가능.
  - 유한 모집단 보정 공식: 95% 신뢰수준과 10% 오차범위를 적용하여, 전체 30개 중 단 24개의 표본만 사람이 검수해도 전체의 품질이
    수학적으로 보증됨.

② 층화 표집 (stratified_sample) & 블라인드 믹싱

  - take = max(1, int(round(n * len(group) / total))): 난이도별 바구니에서 원래 비율(5:3:2)을
    토씨 하나 안 틀리고 그대로 유지하며 24개 추출.
  - 블라인드 믹싱: 통과본과 의심본을 무작위로 섞어(random.shuffle), 검수자가 색안경(확증 편향)을 끼지 못하게 통제.

③ 인간 검수 결과: 16.7% 잠재 불량 적발 & 파이프라인 진화

  - 24개를 정밀 검수했더니 불량 4건(불량률 16.7%) 적발!
  - 불량 원인: Qwen 모델이 안건 3개를 1줄로 퉁쳐서 합쳐버리는 꼼수(논의사항 개수 불일치)를 부림.
  - 파이프라인 피드백 루프:
    사람이 4개를 손으로 고치는 게 아니라, 파이프라인에 filter_structure(개수 일치 검사)를 새로 장착하여 불량 5건을 전량
    자동 박멸 (30건 ➔ 25건 순수 골든셋 확정).

7. 데이터 누수 방지 분할 & 데이터셋 카드 출하

① 출처 단위 분할 (split_by_source)

  - 데이터 누수(Data Leakage) 차단:
    동일한 원본 회의록(source_seed)에서 나온 파생 데이터가 Train과 Test에 나뉘어 들어가면 모델이 문제를 외워버림.
  - assert not overlap: Train(17), Valid(3), Test(5)가 공유하는 source_seed 교집합이 0건임을
    수학적으로 강제.

② dataset_card.json (데이터셋의 주민등록증)

  - 라이선스: Apache-2.0, 사내 전용 명시 (사내 기밀 데이터 미사용 입증).
  - 리니지(시간 스냅샷): 1월 13일 ~ 11월 23일, 시드 범위, 원문 변경 시 롤백 정책 기록.
  - 투명한 한계점 고백 (known_limitations): 3B 모델 한계, 16.7% 표본 불량률, 전수 검수 미수행 사실을 솔직하게
    기록하여 신뢰도 확보.

③ 표준 포맷 출하 (sft_train.jsonl)

  - 스탠퍼드 Alpaca 표준 규격:
    {"instruction": "회의록을 표준 서식으로 재작성하세요.", "input": "...", "output": "..."}
  - Hugging Face SFTTrainer, Unsloth, Axolotl에 파일 경로만 던지면 즉시 학습 가능한 완성품 형태로 저장
    완료!

8. 💡 [실무 플러스] 시니어가 반드시 알아야 할 지식 (Bonus Pro-Tips)

Tip 1. "착한 노이즈" vs "나쁜 노이즈" 구분법

  - 약이 되는 착한 노이즈 (다양성):
    구어체 말투, 사소한 줄바꿈 오타, 다양한 어미 변화. ➔ 모델이 거친 현실 세계 사용자를 만났을 때 멘붕하지 않게 해주는
    '예방주사/보약'!
  - 독이 되는 나쁜 노이즈 (사실/문법 왜곡):
    "협의 ➔ 혐의" 단어 왜곡, 날짜/인명 날조, 개수 누락. ➔ 모델을 사기꾼으로 만드는 **'치명적 독약'**이므로 필터로 무조건
    박멸!
  - 결론: 100% 무균실을 고집하느라 돈을 낭비하지 말고, 나쁜 독약만 확실히 거른 뒤 98% 순도에서 타협하는 것이 실무의 정석.

Tip 2. SFT vs LoRA 용어의 올바른 정리

  - SFT (지도 미세조정): 문제와 정답을 주고 공부시키는 '학습 목적/방식' 그 자체.
  - Full-SFT: 뇌세포 100%를 다 고치며 학습 (비싸고 망각 위험 큼).
  - LoRA-SFT: 뇌세포는 얼리고 0.1% 어댑터만 장착하여 학습 (저렴하고 안전함).
  - 👉 "일반적인 전체 파인튜닝(Full-SFT) 대신, LoRA 방식으로 SFT를 진행하는 것이 소형 모델의 지능을 보존하는 최고의
    선택이다!"

Tip 3. 멀티 어댑터 (Multi-LoRA) 아키텍처

  - LoRA는 행렬 덧셈(W_{base} + \Delta W_1 + \Delta W_2)이므로 어댑터를 2개 이상 동시 장착 가능.
  - [어댑터 A: 회의록 마크다운 양식 스킬 (50MB)] + [어댑터 B: 사내 인사 규정 도메인 지식 (50MB)]를 한 베이스 모델에
    동시에 끼워 맞춤형 AI 구현.

Tip 4. A/B 테스트 0점의 진짜 이유 & 프로덕션 레시피

  - 오늘 실습에서 A/B 모델이 둘 다 0점을 맞은 이유: 코랩 시간 절약을 위해 1에포크(33초, 딱 4스텝)만 돌리고 프롬프트에 양식
    힌트를 안 줬기 때문. (배관 연결 점검용 Dry-Run).
  - 실무 권장 레시피:
      - 데이터: 300 ~ 1,000건
      - 에포크: 3 ~ 5 에포크 (약 20~30분 학습)
      - ➔ 이 세팅으로 돌리면 정제 데이터 모델(B)이 85~90점을 찍고, 날것 모델(A)은 40점대에 머물며 40점 이상의 압도적
        품질 격차가 실제로 증명됨!

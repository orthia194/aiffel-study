
| 층 | 다루는 것 | 단위 | 대표 작업 | 우리가 나눈 대화와의 연결점 |
| --- | --- | --- | --- | --- |
| **1 · 프롬프트** | 모델에게 하는 요청의 문면 | 한 번의 요청 | 명세 작성, 출력 형식 지정 | "JSON으로 요약해 줘", "질문에 정확히 답변해 줘"와 같이 LLM에 전달하는 **직접적인 지시문**입니다.|
| **2 · 컨텍스트** | 창에 무엇을 넣을지 | 한 번의 호출 | 선별, 압축, 외부화, 배치 | **컨텍스트 윈도우 예산 관리** 영역입니다. 토큰이 차오르는 것에 대비해 이전 대화를 잘라내고(Truncate), RAG에서 꼭 필요한 사실만 뽑아 넣어주는 영역입니다.|
| **3 · 하네스** | 모델을 둘러싼 구조물 | 한 번의 작업 | 도구, 규약, 검증 장치, 실행 환경 | **제어 및 안전망 파이프라인**입니다. 사서 에이전트(전처리), 오작동 방지 코드, 외부 도구(Vector DB) 연결 및 예외 처리를 감싸는 외부 파이썬 코드 전체입니다.|
| **4 · 루프** | 작업을 반복하는 방식 | 여러 번의 작업 | 컴팩션, 노트, 분할, 종료 조건 | **에이전트의 지속적 실행 메커니즘**입니다. 대화가 길어질 때 메모리를 요약 및 압축(컴팩션)하고, 작업을 여러 단계로 나누어 목표 달성 시까지 반복·종료를 제어합니다.|


### 💡 핵심 요약

* **프롬프트 & 컨텍스트:** LLM에게 **무엇을 읽히고 지시할 것인가**(입력 메시지와 토큰 예산 관리)

* **하네스 & 루프:** LLM을 감싸서 **시스템이 실수 없이 무한히/자동으로 돌아가게 만드는 코드 구조**(전처리 에이전트, RAG 연동, 메모리 압축 루프)

---

### 1. 프롬프트 층이란?

모델에게 전달하는 **‘단일 요청 메시지의 문문(Text)’** 그 자체를 다루는 최하단 레이어입니다. LLM이 사용자의 의도를 정확히 이해하고 원하는 형식으로 답변하도록 만드는 **작업 지시서** 역할을 합니다.


### 2. 주요 구성 요소 (Structure)

실무 에이전트 개발 시 프롬프트는 보통 3가지 파트로 분할되어 구성됩니다.

1. **시스템 프롬프트 (System Prompt / Persona)**
* 에이전트의 역할, 정체성, 행동 규칙, 제약 사항을 정의합니다.
* *예시: "너는 법률 문서 전처리 전문 에이전트야. 약관을 읽고 핵심 조항을 JSON으로만 추출해."*


2. **지시 및 조건 (Instructions & Constraints)**
* 수행해야 할 구체적인 미션과 하지 말아야 할 행동(가드레일)을 지정합니다.
* *예시: "추측해서 답변하지 말고, 제공된 문서 내용에만 기반해 답변해."*


3. **출력 스키마/형식 지정 (Output Format / Few-Shot)**
* JSON, XML, Markdown 등 원하는 결과물 구조를 명시하거나 예시(Few-Shot)를 제공합니다.
* *예시: `{"section_id": "7조", "summary": "..."}` 형태로 출력할 것.*



### 3. 대표 작업 (Representative Tasks)



* **명세 작성 (Specification):** AI가 수행해야 할 과제를 명확하고 모호하지 않게 정의하는 작업.


* **출력 형식 지정 (Formatting):** 다음 단계를 맡을 에이전트나 코드가 파싱하기 쉽도록 규격화된 포맷(JSON 등)을 강제하는 작업.


* **역할 및 제약 설정 (Role & Guardrails):** AI가 거짓 정보를 말하거나 할루시네이션을 일으키지 않도록 범위 한정.



### 4. 에이전트 아키텍처에서의 중요성

우리가 앞에서 논의했던 ‘사서 에이전트(문서정리 LLM)’를 만들 때도 가장 먼저 프롬프트 층에서 다음과 같이 명서를 작성하게 됩니다.

> *"너는 문서 정리 사서다. 들어오는 약관 텍스트를 제O조 단위로 잘라내고, 각 조항마다 3줄 요약과 핵심 키워드 5개를 추출하여 JSON 규격으로 출력하라."*
> 

이처럼 프롬프트 층은 **한 번의 호출(Single Request) 내에서 AI의 동작 표준을 만들어내는 기본 뼈대**가 됩니다.

---


### 1. 컨텍스트 층이란?

프롬프트가 '어떻게 지시할 것인가'라면, 컨텍스트 층은 "이번 한 번의 LLM 호출 창(Window)에 어떤 정보들을 골라 집어넣을 것인가?"를 관리하는 계층입니다.

LLM의 컨텍스트 윈도우는 제한된 '작업대(RAM)'와 같기 때문에, 제한된 용량 안에서 답변에 꼭 필요한 알짜배기 정보만 효율적으로 배치하는 것이 핵심입니다.



### 2. 주요 구성 요소 (What goes into Context?)

한 번의 LLM 호출 시 컨텍스트 윈도우 채워지는 요소들은 다음과 같습니다:

1. **System Prompt & Instructions:** 1층에서 작성한 기본 지침
2. **Short-term Conversation History:** 직전까지 주고받은 몇 개의 대화 내역 (User & Assistant)
3. **Retrieved Knowledge (RAG):** RAG를 통해 DB에서 가져온 관련 문서 조각(Chunk)
4. **Tool Results:** 에이전트가 실행한 도구(API, 코드 등)의 결과값



### 3. 대표 작업 (Representative Tasks)



* **선별 (Selection):** 전체 대화 기록과 DB의 수많은 지식 중, **현재 질문을 해결하는 데 진짜 필요한 정보만 핀셋처럼 고르는 작업**입니다 (Vector DB Retrieval 등).


* **압축 (Compression):** 긴 대화 내역이나 검색된 문서가 너무 길 때, 토큰 절약을 위해 **핵심 사실(Fact)만 남기고 요약**하여 컨텍스트에 넣는 작업입니다.


* **외부화 (Externalization):** 당장 사용하지 않는 대화 기록이나 지식을 컨텍스트 밖(Vector DB, RAG, 파일 등)으로 빼두는 작업입니다.


* **배치 (Placement / Context Structuring):** 고른 정보들을 어느 위치에 배치할지 구조화하는 작업입니다. (예: LLM이 놓치기 쉬운 중간 정보 대신, **중요 지침을 컨텍스트의 맨 앞이나 맨 뒤에 배치**하는 Lost in the Middle 방지 기법).



### 4. 에이전트 아키텍처에서의 중요성

앞서 다룬 "사서 에이전트가 텍스트를 정리하고, 오랫동안 누적된 대화를 비워내며 RAG로 빼두는 전략"이 모두 이 컨텍스트 층의 관리 기법입니다.

* 대화가 길어져 토큰 한도에 다다르면 오래된 대화를 외부화(RAG 저장)하여 컨텍스트 공간을 확보합니다.


* 질문이 들어왔을 때 관련 정보만 **선별 및 압축**해서 컨텍스트에 부어줌으로써, 최소한의 비용과 높은 정확도로 최적의 답변을 이끌어냅니다.

---


### 1. 하네스 층이란?

프롬프트와 컨텍스트가 LLM 내부로 들어가는 '입력값'을 다룬다면, 하네스 층은 **"LLM 외부에서 모델을 둘러싸고 흐름을 제어하는 코드 구조물과 실행 환경"** 전체를 의미합니다.

말을 제어하는 고삐(Harness)처럼, **지능을 가진 LLM이 환각을 일으키거나 탈선하지 않고 정해진 목표를 정확히 수행하도록 제어하고 보좌하는 프레임워크**입니다.



### 2. 주요 구성 요소 (Components)

1. **도구 연동 (Tool Integration / MCP):**
* LLM이 스스로 할 수 없는 연산, 검색, DB 조회, 파일 쓰기 등을 수행할 수 있도록 외부 API나 Python 도구를 연결해 줍니다.


2. **규약 및 가드레일 (Protocols & Guardrails):**
* LLM의 입출력을 검증합니다. (예: 대화 저장 전 잡담을 걸러내는 데이터 위생 로직, 민감 정보 필터링, JSON 포맷 검증).


3. **오류 복구 및 피드백 (Error Handling & Self-Correction):**
* LLM이 잘못된 코드나 유효하지 않은 포맷을 출력했을 때, 에러 메시지를 다시 LLM에게 전달하여 스스로 수정하도록 유도하는 제어 흐름입니다.



### 3. 대표 작업 (Representative Tasks)



* **도구 (Tools):** Vector DB, 웹 검색, 코드 실행기, PDF 생성기 등을 에이전트에 바인딩하는 작업.


* **규약 (Protocols):** 에이전트 간 데이터 전달 방식, 스키마, 통신 규칙을 규정하는 작업.


* **검증 장치 (Validation):** LLM의 출력이 가이드라인에 맞는지 검사하고, 오작동 시 재시도(Retry) 루프를 태우는 작업.


* **실행 환경 (Execution Environment):** 에이전트 코드가 안전하게 동작할 수 있는 격리된 샌드박스(Sandbox)나 파이프라인 구축.



### 4. 에이전트 아키텍처에서의 중요성

앞서 다룬 "사서 에이전트"를 예로 들면:

* 약관 텍스트가 들어왔을 때 사서 LLM을 호출하고,
* 그 결과를 받아 임베딩 모델로 보낸 뒤 Vector DB에 `upsert`하는 **전체 파이썬 파이프라인 코드**가 바로 하네스 층입니다.

LLM 자체는 그저 텍스트를 생성하는 엔진일 뿐이며, **하네스 층이 존재해야 비로소 '스스로 동작하는 에이전트'가 탄생**합니다.

---

### 1. 루프 층이란?

단일 실행(One-shot)으로 끝나는 일회성 작업을 넘어, "목표를 달성할 때까지 여러 단계의 작업을 어떤 흐름으로 반복하고 관리할 것인가?"를 다루는 최상위 계층입니다.

복잡한 과제를 해결하기 위해 에이전트가 생각(Reasoning) $\rightarrow$ 행동(Action) $\rightarrow$ 관찰(Observation)의 과정을 스스로 계속 거치도록 만드는 **상태 관리 및 순환 제어 메커니즘**입니다.



### 2. 주요 구성 요소 (Components)

1. **상태 관리 (State Management):**
* 현재 에이전트가 어떤 단계까지 진행했는지, 어떤 정보를 확보했는지를 기억하고 업데이트합니다. (예: LangGraph의 State, Autogen의 대화 상태 등)


2. **복합 과제 분할 (Task Decomposition):**
* "약관 검토 후 보고서 작성"이라는 큰 목표를 [1. 파싱] $\rightarrow$ [2. 조항 분석] $\rightarrow$ [3. 위험요소 추출] $\rightarrow$ [4. 보고서 작성]으로 쪼개어 단계별로 실행시킵니다.


3. **종료 조건 판단 (Termination Control):**
* 목표가 달성되었는지, 무한 루프에 빠지지 않았는지, 최대 반복 횟수에 도달했는지를 체크하여 작업을 안전하게 마무리시킵니다.



### 3. 대표 작업 (Representative Tasks)



* **컴팩션 (Compaction / Memory Compression):**
* 루프가 반복되면서 쌓인 긴 대화/작업 내역을 요약·압축하여 토큰 오버플로우를 막고 핵심 기억만 남기는 작업입니다.




* **노트 (Notes / Scratchpad):**
* 에이전트가 중간 작업 결과를 일기장이나 메모장(Scratchpad)처럼 기록하며 다음 단계의 계획을 세우는 작업입니다.




* **분할 (Decomposition):**
* 풀기 힘든 큰 문제를 여러 개의 하위 루프(Sub-loop) 작업으로 잘라내는 작업입니다.




* **종료 조건 (Termination Conditions):**
* "원하는 답을 얻었는가?", "에러가 3회 이상 지속되었는가?" 등을 판단하여 루프를 탈출시키는 작업입니다.



### 4. 에이전트 아키텍처에서의 중요성

앞서 정리했던 전체 구조를 종합해 보면:

* **프롬프트:** "무엇을 할지" 지시문을 작성하고


* **컨텍스트:** "어떤 지식"을 넣을지 선별하며


* **하네스:** 도구 연동 및 안전장치를 감싸고


* **루프:** 이 모든 과정을 **목표가 완성될 때까지 끊임없이 반복하며 스스로 메모리를 압축하고 제어**하게 만듭니다.



즉, **루프 층이 완성되어야 단순한 일회성 AI 호출을 넘어, 스스로 피드백을 주고받으며 복잡한 문제를 끝까지 해결하는 완전한 '자율형 AI 에이전트'가 작동**하게 됩니다.

---

### 💡 4개 계층 전체 최종 요약

1. **프롬프트:** 모델에게 전달하는 지시문


2. **컨텍스트:** 이번 호출의 윈도우 채우기 및 토큰 관리


3. **하네스:** 모델 주변을 감싸는 외부 코드 및 도구 제어 시스템


4. **루프:** 목표 달성을 위해 작업을 반복하고 메모리를 유지하는 전체 순환 구조


하네스(Harness)가 강력할수록 에이전트의 안정성과 정확도가 비약적으로 상승하지만, **하네스 역시 기본 지능(LLM의 한계)을 완전히 넘어서지는 못하는 영역**이 존재합니다.

실무에서 하네스로 해결할 수 있는 부분과 해결할 수 없는 한계를 분명하게 정리해 드립니다.

---

### 🛡️ 1. 하네스로 커버가 가능한 목록 (Harness로 해결)

하네스는 주로 **"규칙 준수, 포맷 유지, 프로세스 제어, 오작동 복구"** 영역에서 강력한 힘을 발휘합니다.

* **출력 형침 및 규약 준수 (Format Enforcement):**
* LLM이 JSON/XML 형식을 깨뜨렸을 때, 하네스가 에러를 감지하고 *"포맷 오류 발생, 다시 JSON으로 출력해"*라며 재시도(Retry) 루프를 돌려 100% 규격화된 출력을 보장합니다.


* **환각 및 사실 기반 검증 (Hallucination Guardrails):**
* LLM의 답변과 RAG 원문 데이터를 대조하여 출처가 없거나 지어낸 답변일 경우, 답변을 즉시 백트랙(되돌리기)하여 재검토시킵니다.


* **도구 호출 및 실행 매개변수 보정 (Tool Calling Safety):**
* LLM이 API 파라미터나 SQL 쿼리를 잘못 생성했을 때, 하네스의 인터셉터(Interceptor)가 구문 오류를 미리 잡아내고 정확한 인자값으로 수정하여 재호출합니다.


* **무한 루프 및 타임아웃 방지 (Flow Control):**
* 에이전트가 동일한 작업을 계속 반복하거나 멍하니 갇혀 있을 때, 최대 반복 횟수(Max Loops)를 제한하고 강제 종료 및 대체 플랜(Fallback)을 실행시킵니다.


* **컨텍스트 오버플로우 관리 (Context Management):**
* 대화가 길어져 토큰 한도를 넘어가려 할 때, 하네스가 자동으로 오래된 대화를 요약/압축(Compaction)하고 Vector DB로 밀어 넣습니다.


### ⚠️ 2. 하네스로 커버가 불가능한 목록 (LLM 지능의 한계)

하네스는 '안전망과 제어 장치'일 뿐, **모델 자체가 가진 근본적인 추론 능력이나 지식을 새로 만들어낼 수는 없습니다.**

* **고차원적인 고난도 추론 (High-Level Reasoning):**
* 복잡한 수학 문제 해결, 기발한 비즈니스 아이디어 발상, 복잡한 법률 조항 간의 상충 관계 판단 등 **본질적인 '지능'이 필요한 영역**은 소형/저성능 모델에 하네스를 붙여도 고성능 모델을 따라잡을 수 없습니다.


* **제로샷 도메인 지식 (Zero-shot Domain Knowledge):**
* 모델이 사전 학습 과정에서 배우지 못한 전문 지식이나 최신 정보는 하네스가 아무리 훌륭해도 스스로 알아낼 수 없습니다. (RAG를 통한 외부 지식 주입이 필수적입니다.)


* **초기 의도 파악의 완전한 오류 (Intent Misunderstanding):**
* 사용자의 모호하거나 중의적인 질문을 모델이 완전히 잘못 해석하여 엉뚱한 방향으로 작업을 시작해 버리면, 하네스는 그 잘못된 방향 안에서만 정상 동작을 유지할 뿐 초반의 그릇된 판단 자체를 교정하기 어렵습니다.


* **언어적 유연성 및 감성 품질 (Prose & Nuance):**
* 문장의 자연스러운 뉘앙스, 창의적인 카피라이팅, 감성적인 대화 능력 등 정성적인 표현력의 체급 차이는 하네스로 메울 수 없습니다.


### 💡 한 줄 요약

* **하네스로 해결 가능한 것:** 시스템의 **신뢰성, 안전성, 규격 준수, 에러 복구, 비용 절감** (결함 방지)


* **하네스로 불가능한 것:** 모델 본연의 **추론 능력, 창의성, 깊은 도메인 지식** (지능 상한선)

따라서 **"어느 정도 기본 추론이 가능한 모델(예: GPT-4o-mini, Claude Haiku)"** 수준에 "강력한 하네스"를 결합하는 것이 실무에서 가성비와 안정성을 모두 잡는 최적의 조합이 됩니다!

* **`.pt / .pth` :** 공방에서 작업 중인 **"원자재 / 작업용 설계도"** (파이토치 전용 파일)
* **`ONNX` :** 어디서든 가볍게 돌아가도록 깎아낸 **"만국 공통 규격 완제품"** (경량화 표준 포맷)
* **`vLLM` :** 거대 LLM을 초고속으로 돌려주는 **"슈퍼카 엔진 (서버 프로그램)"** (파일 포맷이 아니라 엔진!)

---

### 📊 한눈에 비교하는 3대 기술 요약표

| 비교 항목 | `.pt / .pth` | `ONNX` (`.onnx`) | `vLLM` |
| :--- | :--- | :--- | :--- |
| **정체** | 파이토치 **자체 모델 저장 포맷** | 플랫폼 독립적인 **오픈 표준 포맷** | LLM 전용 **고속 추론 서버/엔진** |
| **주 사용 단계** | 모델 연구, **학습(Training)**, 파인튜닝 | 모델 경량화, **일반 모델 서빙(배포)** | 거대 언어 모델(LLM) **실시간 서빙** |
| **잘 맞는 모델** | 모든 AI 모델 (개발 단계) | **임베딩(E5, BGE-M3)**, 비전(YOLO), 음성 | **텍스트 생성형 LLM** (Qwen, Llama 등) |
| **실행 필요 환경** | Python + 거대한 `torch` 라이브러리 | 초경량 `onnxruntime` (C++, JS, 모바일 가능) | 고성능 GPU (NVIDIA CUDA) |
| **주요 장점** | 코드 수정 없이 파이토치와 100% 호환 | 깃털 같은 용량, 파이토치 불필요, 2~3배 가속 | **연속 배칭, VRAM 낭비 0%**, 3~4배 초고속 |
| **한계점** | 무겁고(2~4GB), 파이썬 밖에서 배포 어려움 | 생성형 LLM(KV 캐시) 변환이 매우 까다로움 | 생성형 LLM 외(이미지, 임베딩)에는 못 씀 |

### 1. `.pt` / `.pth` (PyTorch Native Format)

> **"파이토치로 방금 구워낸 따끈따끈한 원본 모델"**

* **정체:** 파이토치에서 `torch.save()`를 쳤을 때 생기는 파이썬 딕셔너리 기반 바이너리 파일입니다.
* **언제 쓸까?**
  * 모델을 연구실에서 개발하고 학습시킬 때
  * LoRA 파인튜닝 체크포인트를 저장하고 불러올 때
  * 개발 단계에서 디버깅할 때
* **장점:**
  * 파이토치와 100% 호환되므로 별도의 변환(Convert) 과정 없이 바로 로드 가능.
  * 옵티마이저 상태, 학습 에포크 수 등 학습 재개에 필요한 정보를 그대로 다 담을 수 있음.
* **단점:**
  * 배포 서버에도 2GB~4GB나 되는 무거운 `torch` 라이브러리를 무조건 깔아야 함.
  * 파이썬 인터프리터(GIL)에 묶여 있어 추론 속도가 느림.
  * 파이썬 `pickle` 기반이라 외부에서 받은 파일 실행 시 악성코드 보안 위험이 있음 (그래서 요즘 허깅페이스는 `.safetensors`로 대체하는 추세).

---

### 2. `ONNX` (Open Neural Network Exchange)

> **"파이토치를 버리고 어디서든 가볍게 돌아가게 만든 만국 공통 규격"**

* **정체:** 마이크로소프트와 메타가 주도해서 만든 **'인공지능 모델계의 PDF 파일'**. 모든 딥러닝 연산을 하나의 정적 수학 그래프로 박제한 파일입니다.
* **언제 쓸까?**
  * **RAG 시스템의 '임베딩 모델(BGE-M3, E5)'이나 '리랭커'를 서빙할 때 (실무 1순위!)**
  * GPU가 없는 **저렴한 일반 CPU 서버**에서 모델을 돌려야 할 때
  * 도커 컨테이너 용량을 수십 MB로 다이어트해서 가볍게 배포하고 싶을 때
  * 파이썬이 없는 C++, C#, 스마트폰 앱(iOS/Android), 웹 브라우저 안에서 AI를 실행할 때
* **장점:**
  * **탈(脫) 파이토치:** 무거운 PyTorch를 지워버리고, 50MB짜리 `onnxruntime`만 깔면 끝.
  * **그래프 최적화:** 중복 연산을 합치고 상수를 미리 계산해 줘서 순수 파이토치보다 1.5~3배 빨라짐.
* **단점:**
  * 파이토치 모델을 ONNX로 변환(`torch.onnx.export`)하는 과정이 은근히 번거로움 (오늘 사진처럼 `dummy_input` 넣고 트레이싱해야 함).
  * 텍스트를 끝없이 생성해야 하는 **거대 LLM(Qwen, Llama)**은 구조상 ONNX로 변환하기가 너무 복잡함.

---

### 3. `vLLM` (Virtual Large Language Model Engine)

> **"거대 LLM만을 위해 태어난 고속 서빙의 끝판왕 (엔진)"**

* **정체:** 파일 포맷이 아니라, **거대 언어 모델(LLM)을 웹서버 형태로 초고속 서빙해 주는 '전문 추론 엔진(소프트웨어)'**입니다.
* **언제 쓸까?**
  * 사내 회의록 요약 챗봇, 사규 Q&A 챗봇 등 **Qwen, Llama 같은 텍스트 생성 LLM을 프로덕션에 배포할 때**
  * 여러 사용자가 동시에 질문을 던지는 동시 접속 환경 (트래픽이 많을 때)
* **장점:**
  * **PagedAttention (VRAM 낭비 0%):** 운영체제의 가상 메모리 페이징처럼 GPU 메모리를 조각조각 쪼개 관리하여, 일반 파이토치 대비 **처리량(Throughput)이 3~4배 급증**.
  * **연속 배칭 (Continuous Batching):** 먼저 끝난 손님은 먼저 내보내고 새 손님을 바로 받아 병렬로 쳐냄.
  * **OpenAI 호환 API 기본 탑재:** 명령어 한 줄(`vllm serve 모델명`)만 치면 지난주에 만든 `/v1/chat/completions` 서버가 자동으로 뜸.
* **단점:**
  * 오직 **'텍스트 생성형 트랜스포머(LLM)'**에만 쓸 수 있음 (이미지 분류, 단순 임베딩 모델에는 못 씀).
  * 엔비디아 고성능 GPU(VRAM) 의존도가 높아서 저사양 CPU 서버에서는 제대로 힘을 못 씀.

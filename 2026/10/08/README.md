첨부해주신 자료는 실무에서 **‘모델 선정 보고서’**를 쓸 때 필요한 핵심 기준을 아주 명확하게 짚고 있습니다. 

혼자 공부할 때는 리더보드 순위가 높고 똑똑한 모델(예: Qwen, Llama 등)을 자유롭게 쓰면 되지만, **실제 프로젝트나 회사 업무에서는 “성능이 좋다고 무조건 쓸 수 있는 것”이 아닙니다.** 

이미지에 나온 **5가지 핵심 관점**을 바탕으로, 실제 모델을 선정할 때 구체적으로 어떤 지표와 조건을 확인해야 하는지 정리해 드립니다.

---

### 1. 법적으로 되나? (라이선스) — *법무팀의 관심사*
가장 먼저 걸러내야 하는 절대적인 1차 필터입니다. 상업적 이용이 불가능하다면 아무리 뛰어난 모델이라도 회사 서비스에 탑재할 수 없습니다.

* **상업적 이용 가능 여부:** 
  * `Apache 2.0`, `MIT`: 제약이 거의 없어 기업에서 가장 선호합니다.
  * 독자 라이선스: MAU(월간 활성 사용자 수) 제한이 있거나(예: Llama의 7억 명 제한), 파생 모델 공개 의무, 별도 승인 필요 여부 등을 확인해야 합니다.
  * *참고(Qwen의 경우):* Qwen 2.5의 대부분 모델은 `Apache 2.0`으로 개방되어 실무 라이선스 통과율이 높지만, 특정 대형 크기나 파생 모델은 개별 라이선스 조항을 확인해야 합니다.
* **학습 데이터 저작권 이슈:** 모델 개발사가 학습에 사용한 데이터에 저작권 분쟁 소지가 없는지 확인합니다.

---

### 2. 우리 서버에 올라가나? (인프라 및 리소스) — *인프라팀의 관심사*
우리 팀/회사가 보유한 GPU 장비나 예산 범위 내의 클라우드 서버에서 실제로 안정적으로 구동되는지 확인해야 합니다.

* **모델 크기와 VRAM(GPU 메모리) 요구량:**
  * 모델 파라미터 수(7B, 14B, 32B, 72B 등)에 따라 필요한 VRAM이 급격히 증가합니다.
  * 단순히 모델을 올리는 것뿐만 아니라, 서빙 프레임워크(vLLM, Ollama, TGI 등)와 동시 접속자(동시 요청 배치), 긴 컨텍스트 윈도우(KV Cache)를 감당할 VRAM 여유가 있는지 계산해야 합니다.
* **양자화(Quantization) 지원:** FP16/BF16 대신 4-bit(AWQ, GPTQ), 8-bit 등으로 경량화했을 때 성능 저하 없이 우리 장비에 올라가는지 확인합니다.
* **추론 속도(Latency)와 처리량(Throughput):** 사용자가 체감하기에 응답 지연(TTFT, Time to First Token)이 너무 길지 않은지 검토합니다.

---

### 3. 한국어가 되나? (언어 및 토크나이저 효율) — *기획/개발팀의 관심사*
다국어 모델이라도 한국어 처리 효율과 문맥 이해도가 떨어지면 사용하기 어렵습니다.

* **한국어 표현력 및 문맥 이해:** 어색한 번역투가 없는지, 한국 문화·법률·도메인 고유명사를 제대로 이해하는지 봅니다.
* **토크나이저(Tokenizer) 효율 (압축률):**
  * 한국어 1글자가 몇 개의 토큰으로 쪼개지는지 확인해야 합니다.
  * 토크나이저가 한국어를 비효율적으로 쪼개면 **추론 속도가 느려지고, 한 번에 처리할 수 있는 글자 수가 줄어들며, API 사용 시 비용이 배로 증가**합니다.
  * *(Qwen의 강점 중 하나가 어휘집(Vocab size)이 커서 동양권 언어의 토큰 압축률이 우수하다는 점입니다.)*

---

### 4. 성능 (태스크 적합도) — *앞의 3가지를 통과한 후보끼리의 경쟁*
이미지에 명시된 대로 **성능은 1~3번을 통과한 후보들 중에서 비교**하는 것입니다. 일반 벤치마크 숫자(MMLU 등)보다 **우리가 만들려는 기능에 맞는 실질적 성능**이 중요합니다.

* **우리의 주 목적(Task)에 맞는 역량:**
  * RAG(검색 증강 생성): 문맥 참조 능력, 환각(Hallucination) 억제력
  * 에이전트/자동화: Function Calling(Tool Use), 구조화된 출력(JSON/YAML) 생성 능력
  * 코딩/추론: 수학적 논리, 코드 생성 정확도
* **자체 평가 셋(Eval Set) 검증:**
  * 공개 벤치마크 점수만 믿지 않고, 실제 서비스에서 발생할 예상 질문 50~100개를 뽑아 정답률을 직접 블라인드 테스트해 봅니다.

---

### 5. 얼마나 드나? (비용 및 TCO) — *의사결정권자의 관심사*
상용 API(OpenAI, Claude 등)를 쓰는 것과 오픈소스 모델(Qwen 등)을 자체 서버에 띄우는 것 중 어느 쪽이 경제적인지 비교합니다.

* **API vs 자체 호스팅(On-Premise/Cloud GPU) 비교:**
  * 트래픽이 적을 때는 종량제 API가 훨씬 저렴합니다.
  * 트래픽이 일정 수준 이상으로 많아지거나 내부 보안 규정(망분리)이 필수라면 자체 호스팅이 유리합니다.
* **총소유비용(TCO, Total Cost of Ownership):**
  * 단순히 GPU 대여료뿐만 아니라 인프라 유지보수 인력, 서버 가동 전력, 모니터링 구축 비용까지 고려해야 합니다.

---

### 💡 실무 관점에서 Qwen을 바라본다면?

공부할 때 쓰셨던 **Qwen(특히 Qwen 2.5 라인업)**은 실무 후보군으로도 매우 강력한 편입니다.
1. **라이선스:** 대다수 모델이 Apache 2.0으로 상업적 도입이 매우 쉬움
2. **서버 적합성:** 0.5B부터 72B까지 크기가 세분화되어 있어 인프라 사양에 맞춤 선택 용이
3. **한국어/토크나이저:** 다국어 어휘집이 매우 커서 한국어 토큰 압축률과 표현력이 글로벌 오픈소스 중 상위권
4. **성능:** 코딩, 수학, Function Calling, 긴 문맥 처리 능력이 우수

따라서 실무 보고서를 작성하실 때는 **"Qwen이 성능이 좋아서 골랐습니다"**가 아니라, **"1) 상업용 무료 라이선스이며, 2) 보유 중인 GPU 사양에서 양자화 서빙이 가능하고, 3) 한국어 토큰 효율이 높아 타 모델 대비 응답 속도 및 비용 면에서 유리하여 최종 선정했습니다"**와 같이 5가지 기준을 순서대로 통과한 근거를 들어 설명하시면 됩니다.

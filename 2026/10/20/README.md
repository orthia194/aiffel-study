# 🏢 사내 비정형 문서 데이터 정제 및 합성 QA 데이터셋 구축 파이프라인
> 기업 내부 문서(규정, 매뉴얼 등)를 정제하여 RAG(검색 증강 생성) 평가 및 sLLM 학습에 즉시 활용할 수 있는 고품질 데이터 파이프라인 구축 프로젝트

---

## 📌 1. 프로젝트 개요 (Overview)
사내에 흩어져 있는 다양한 포맷(PDF, HWPX, DOCX, Markdown 등)의 비정형 문서를 수집하고, **개인정보 보호(PII), 품질 필터링, 중복 제거(Deduplication)** 과정을 거쳐 신뢰할 수 있는 데이터로 정제합니다. 
이후 소형 오픈소스 LLM(`Qwen2.5-3B-Instruct`)을 활용하여 RAG 시스템 벤치마크 및 검색 모델 파인튜닝에 필수적인 **[질문-답변-근거(Q-A-Evidence)] 합성 데이터셋**을 자동으로 생성하고 정합성을 검증합니다.

---

## 🛠️ 2. 기술 스택 (Tech Stack)
* **Language & Environment:** Python 3.10+, Google Colab (Linux / T4 GPU)
* **LLM & Embeddings:** `Qwen/Qwen2.5-3B-Instruct`, `BAAI/bge-m3`
* **Data Processing & Algorithms:** `unicodedata`, `hashlib`, `MinHash / LSH`, `NumPy`, `LangChain`
* **File Parsing:** PyPDF, python-docx, hwpx 등 다양한 사내 포맷 파서

## 🔄 3. 전체 파이프라인 아키텍처 (Pipeline Steps)

```
[원시 사내 문서]
       │
       ▼ (Step 1~4: 수집 및 품질 평가)
  1. 저장소 탐색 ➔ 2. 메타데이터 카탈로그화 ➔ 3. 텍스트 추출/인코딩 ➔ 4. 추출 품질 산출
       │
       ▼ (Step 5~8: 보안 및 정제)
  5. 개인정보(PII) 마스킹 ➔ 6. 저품질 문서 필터링 ➔ 7. 완전/근사 중복 제거 ➔ 8. 통계 보고서
       │
       ▼ (Step 9~10: 합성 및 검증)
  9. LLM 기반 QA 데이터 합성 ➔ 10. 룰 기반 정합성 검증 & 프롬프트 최적화
       │
       ▼
[고품질 골든 데이터셋 (Golden Dataset)]
```

### [Phase 1] 문서 카탈로그화 및 텍스트 수집 (Step 1 ~ 4)
* **Step 1. 사내 문서 저장소 표본 수집:** 다양한 부서와 보안 등급이 혼재된 원본 문서 디렉토리 구조화.
* **Step 2. 1단계 데이터 목록화 (카탈로그 작성):** 파일 해시(SHA-256), 크기, 부서(DEPT), 접근 권한(ACL) 메타데이터 추출.
* **Step 3. 텍스트 수집 및 인코딩 정규화:** 다양한 포맷(.pdf, .docx, .hwpx, .md)에서 본문 텍스트 추출 및 UTF-8 정규화.
* **Step 4. 문서별 추출 품질 지표 산출:** 텍스트 길이, 특수문자 비율, 공백률 등을 분석하여 파싱 완성도 수치화.

### [Phase 2] 데이터 정제 및 거버넌스 (Step 5 ~ 8)
* **Step 5. 2단계 프라이버시 및 규정 준수 (PII 마스킹):** 주민등록번호, 전화번호, 이메일 등 개인정보 자동 탐지 및 마스킹.
* **Step 6. 3단계 문서 단위 품질 필터링:** 빈 문서, 텍스트 길이가 너무 짧거나 깨진 저품질 문서 제거.
* **Step 7. 4단계 완전·근사 중복 제거 (Deduplication):** 
  * 파일 해시 기반 완전 중복 제거
  * MinHash(표현 일치) 및 BGE-M3 임베딩(문맥적 의미 일치)을 결합한 다단계 중복 필터링.
* **Step 8. 전처리 통계 보고서 및 정제 스냅샷:** 정제 전/후 문서 수, 토큰 수 변화 통계 리포트 생성 및 최종 정제 코퍼스 스냅샷 저장.

### [Phase 3] 합성 데이터셋 생성 및 검증 (Step 9 ~ 10)
* **Step 9. 평가·학습용 합성 데이터 생성:**
  * `Qwen2.5-3B-Instruct`를 사용하여 원문 기반 `{"question", "answer", "evidence"}` JSON 세트 대량 자동 생성.
* **Step 10. 합성 데이터 정합성 검증 (Validation):**
  * 원문 내 근거 존재 여부(`근거불일치`), 표현 복사율(`표현복사`), JSON 포맷 결함(`필수필드누락`) 자동 채점 및 필터링.

## 💡 4. 핵심 트러블슈팅 및 성능 최적화 (Key Takeaways)

### ① macOS ↔ Linux 간 유니코드 정규화(NFD vs NFC) 불일치 해결
* **문제:** Mac에서 생성된 파일명이 자모 분리형(NFD, `ㄱ+ㅗ+ㅇ...`)으로 저장되어, 코드 내 딕셔너리 키(`"공용"`)와 매칭되지 않고 권한이 `UNKNOWN`으로 누락됨.
* **해결:** 파이썬 `unicodedata.normalize('NFC', path)`를 적용하여 표준 완성형으로 정규화하여 100% 정상 매핑 달성.

### ② MinHash(자카드) vs 임베딩(코사인) 의미 중복 검출 비교
* **결과:** 의미는 같지만 말투가 다른 문서(Paraphrase) 비교 시,
  * **MinHash 유사도:** `0.055` (단어가 달라 중복 탐지 실패)
  * **BGE-M3 임베딩 유사도:** `0.697` (**전체 1위로 중복 탐지 성공**)
  * 👉 **의미론적 중복 검출에는 고밀도 임베딩 모델 도입이 필수적임을 증명.**

### ③ 소형 LLM(3B)의 인지 과부하 극복 & 합성 데이터 최적화
* **문제:** 3B 소형 모델에 복잡한 부정문 제약("10글자 이상 복사 금지" 등)을 부여하자 인지 과부하로 JSON 파싱 에러 및 통과율 급락(57%) 발생.
* **최적화 전략:**
  1. **프롬프트 슬림화:** "본문 한 문장 그대로 복사", "구어체 변환" 등 핵심 규칙 2개로 단순화.
  2. **Temperature 튜닝 (A/B Test):**
     * `0.2` : 문맥 반복 및 조기 출력 중단으로 JSON 파싱 대량 실패
     * `0.4` : 27쌍 생성 / 통과율 70% (유효 19쌍)
     * **`0.7` : 25쌍 생성 / 통과율 80% (유효 20쌍, 최종 채택) 🔥**
* **결과:** 기준 모델(14쌍) 대비 **유효 골든 데이터 수확량 +43% 증가 달성**.

## 🎯 5. 데이터셋 활용 방안 (Future Applications)
1. **RAG 시스템 벤치마크 (Evaluation):** 검색기(Retriever)와 생성기(LLM)의 정확도를 자동 채점하는 Golden Testset으로 활용.
2. **사내 전용 검색 모델 파인튜닝:** `question` $\leftrightarrow$ `evidence` 쌍을 활용하여 `BGE-M3` 임베딩 모델의 대조 학습(Contrastive Learning)에 활용.
3. **시맨틱 캐시(Semantic Cache) 구축:** 자주 묻는 사내 질문을 사전 임베딩하여 0.1초 이내 무비용 고속 응답 파이프라인 구현.

# 📚 언어의 분류: 자연어, 구성된 언어, 인공 언어

> 자연어 처리(NLP)와 인공지능 연구의 바탕이 되는 언어의 유형별 정의, 특징 및 차이점 정리

---

## 1. 자연어 (Natural Language)
인간이 사회적 상호작용과 소통을 통해 의도하지 않고 자연스럽게 발전시켜 온 언어입니다.

- **주요 특징**:
  - **자유로운 영혼**: 인위적인 규정이나 지침을 따르지 않으며, 화자들의 대화와 문화를 반영하며 끊임없이 변화 및 진화합니다. (예: 빅토리아 시대 영어 vs 현대 영어)
  - **원어민 존재**: 태어날 때부터 해당 언어를 습득해 사용하는 원어민(Native Speaker)이 존재합니다.
  - **다양한 변종 생성**: 영어의 혼합어(Konglish, Hinglish 등)처럼 언어 간 상호작용으로 새로운 변형이 생겨납니다.

---

## 2. 구성된 언어 (Constructed Language, Conlang)
특정 목적을 달성하기 위해 인간이 의도적으로 음운론, 문법, 어휘를 고안 및 설계한 언어입니다.

- **주요 특징**:
  - **목적성**: 모국어가 다른 사람들과의 소통 장벽을 극복하거나, 특정 매체/기계와의 통신을 위해 제작되었습니다.
  - **범주**: 인공어(Artificial), 계획어(Planned), 허구의 언어(Fictional) 등을 포함하는 상위 개념입니다.
- **대표 예시**:
  - **국제 통신/기호**: 에스페란토(Esperanto), 모스 부호(Morse Code)
  - **창작/허구의 언어**: 아바타의 나비어(Na'vi), 반지의 제왕의 엘프어(Elvish), 왕좌의 게임의 도트락어(Dothraki)
  - **프로그래밍/마크업 언어**: Python, C++, Java, HTML, XML 등 (기계와 인간 간의 명령 및 의사소통을 위해 설계됨)

---

## 3. 인공 언어 (Artificial Language)
주로 **진화 언어학(Evolutionary Linguistics) 실험 및 연구**를 목적으로 개발되는 매우 제한적인 언어입니다.

- **주요 특징**:
  - **실험 중심 (Short Life-span)**: 특정 문법 규칙(어순, 격 등)이나 언어 동역학 연구용으로 설계되어 실험 종료 후에는 거의 사용되지 않습니다.
  - **제한된 규모**: 실험의 통제와 유효성을 위해 수백만 개의 어휘 대신 작고 엄격하게 제한된 어휘/문법 구조를 가집니다.

---

## 💡 핵심 차이점 요약 (Comparison)

| 구분 | 자연어 (Natural) | 구성된 언어 (Constructed) | 인공 언어 (Artificial) |
| :--- | :--- | :--- | :--- |
| **생성 주체** | 사회적 집단의 자연 발생적 진화 | 인간의 인위적 설계 및 의도적 고안 | 연구자의 실험적 설계 |
| **주요 목적** | 일상적 의사소통 및 소통 | 언어 장벽 극복, 기계 통신, 창작 | 언어학 실험 및 과학적 검증 |
| **특징** | 원어민 존재, 유연함, 규칙 가변적 | 규칙 규범적, 목적에 맞춘 명확성 | 매우 작은 어휘/문법, 단기 수명 |
| **예시** | 한국어, 영어, 스페인어 등 | 에스페란토, 모스부호, Python | 진화 언어학 실험용 언어 |


### 📊 자연어 vs 프로그래밍 언어 (형식 언어 이론 기준)

| 비교 항목 | 프로그래밍 언어 (Programming Language) | 자연어 (Natural Language) |
| :--- | :--- | :--- |
| **형식 언어 분류** | **문맥 자유 문법 (Context-Free Grammar, CFG)** | **문맥 의존 문법 (Context-Sensitive Grammar, CSG)** 이상 |
| **촘스키 계층** | **Type-2** (문맥 자유 언어) | **Type-1** (또는 약한 문맥 의존 언어, Mildly CSG) |
| **구문 파싱 기계** | 푸시다운 오토마타 (Pushdown Automata) | 선형 구속 오토마타 (LBA) / 튜링 기계 (Turing Machine) |
| **모호성 (Ambiguity)** | **없음** (컴퓨터 해석을 위해 오직 하나의 의미만 가짐) | **매우 높음** (동일 문장도 앞뒤 맥락과 상황에 따라 의미가 변함) |
| **문법적 유연성** | **엄격함** (문법 오류 시 컴파일/실행 불가) | **유연함** (문법이 틀려도 맥락을 통해 의미 전달 가능) |


## 🧹 자연어 데이터의 노이즈 유형 및 전처리 가이드

자연어 처리(NLP) 파이프라인에서 원천 데이터에 포함된 노이즈를 정제(Cleaning)하고 정규화(Normalization)하는 작업은 모델의 문맥 이해도와 성능을 결정짓는 핵심 단계입니다.

---

### 📊 1. 자연어 노이즈의 주요 종류

| 노이즈 유형 | 상세 설명 | 대표 예시 | 비고 / 원인 |
| :--- | :--- | :--- | :--- |
| **대소문자 오남용 (Capitalization)** | 대소문자 혼용, 전체 대문자(강조), 고유명사 소문자 표기 | `PLEASE HELP ME`, `iphone`, `gOoD mOrNiNg` | 감정 강조, 모바일 자동완성, 사용자 습관 |
| **문장부호 남용 및 생략 (Punctuation)** | 문장부호의 과도한 반복 또는 마침표/쉼표 생략으로 문장 경계 모호 | `진짜??????`, `응 아니야 ㅋㅋㅋ`, `안녕, , ,` | 감정 표현, 빠른 메신저 대화 습관 |
| **이어서 말하기 / 문장 분절 (Segmentation)** | 한 문장을 완성하지 않고 여러 메시지로 나누어 보내는 현상 | `11:00 - 나 방금`<br>`11:00 - 도착했어`<br>`11:01 - 빨리 나와` | 메신저/채팅 특유의 소통 방식 |
| **대화 간 시간 텀 (Turn-taking Delay)** | 대화 상대와의 응답 시간 격차로 인한 맥락 단절 및 주제 변경 | `10:00 - 점심 뭐 먹을까?`<br>`12:30 - 아 미안 이제 봤다` | 비동기식 대화의 한계, 세션 처리 난제 |
| **철자 및 오탈자 (Typo/Spelling)** | 자음/모음 오타, 키보드 입력 실수, 표준어가 아닌 표현 | `안녕하세용`, `확인부타드립니다`, `Thx` | 사용자 입력 실수, 신조어, 줄임말 |
| **문법 및 띄어쓰기 오류** | 띄어쓰기 누락/오남용, 조사 오용, 주어-동사 불일치 | `아버지가방에들어가신다`, `그가 나를 보았다` | 대화체 특성, 빠른 입력 습관 |
| **특수문자 및 기호 (Special Characters)** | 의미 전달과 무관한 기호, 이모티콘, HTML 태그 | `안녕하세요!!!^^`, `<div>내용</div>`, `&amp;` | 웹 크롤링 부산물, 감정 표현 남발 |
| **음성 인식 이상 (ASR Noise)** | 음성-텍스트 변환(STT) 과정에서 비슷한 발음으로 잘못 변환된 텍스트 | `아이폰` $\rightarrow$ `아이폼`, `가까이` $\rightarrow$ `까까이` | 음성 인식(STT) 모델의 한계 |
| **구조적/포맷 노이즈** | 개행 문자 남발, 깨진 인코딩(깨진 글자), 불필요한 공백 | `안\n녕\nhas\x80`, ` ` | 파일 인코딩(UTF-8) 미치합, 복사 오류 |
| **불용어 및 개인정보 (Noise/PII)** | 분석에 도움이 안 되는 무의미한 단어, 이메일, 전화번호 등 민감 정보 | `그냥`, `어쩌구`, `010-1234-5678` | 크롤링 원본 데이터 내 민감 정보 |

### 🛠️ 2. 전처리 시 주요 고려사항

* **메신저/대화체 데이터 세션 병합 (Session Concatenation)**
  * 동일한 화자가 짧은 시간 텀(예: 3분 이내) 동안 나누어 보낸 연속 메시지는 **하나의 문장으로 병합(Concatenation)**하는 전처리 로직을 적용해야 모델이 전체 문맥을 제대로 파악할 수 있습니다.
* **대소문자 정규화 (Case Normalization)**
  * 영어 NLP 모델 구축 시 대소문자가 단어의 의미 구분에 결정적이지 않은 도메인이라면, 전체 텍스트를 소문자화(`lower()`)하여 단어장(Vocabulary)의 크기를 줄이고 데이터 희소성(Sparsity) 문제를 완화합니다.

## 📐 텍스트 표현 및 벡터 공간 (Text Representation & Embeddings)

컴퓨터가 자연어를 이해하기 위해서는 텍스트를 숫자 형태의 벡터(Vector)로 변환해야 합니다. 기존의 희소 표현 방식에서 고차원 밀집 벡터 공간으로 발전해 온 과정과 원리를 정리합니다.

---

### 1. 원-핫 인코딩 (One-Hot Encoding)과 한계

원-핫 인코딩은 단어장(Vocabulary)의 크기 $N$만큼의 차원을 가진 벡터에서, 해당 단어의 위치에만 `1`을 부여하고 나머지는 모두 `0`으로 채우는 방식입니다.

* **희소성 (Sparsity) 문제**: 단어장이 커질수록 벡터의 차원이 수만~수십만으로 거대해지며, 대부분의 값이 `0`으로 채워져 메모리가 크게 Waste됩니다.
* **의미적 직교성 (Orthogonality)**: 모든 단어 벡터 간의 내적(Dot Product)이 `0`이 되어, 단어 간의 **의미적 유사도나 연관성을 전혀 표현할 수 없습니다.**
  * 예: $\text{Vector}(\text{"사과"}) \cdot \text{Vector}(\text{"바나나"}) = 0$ (과일이라는 공통점 파악 불가)

---

### 2. 밀집 임베딩 (Dense Embedding)

단어를 고정된 저차원(예: 128, 512, 1024차원)의 **실수(Real Number) 벡터** 공간에 매핑하는 방식입니다.

* **공간 효율성**: 0이 아닌 의미 있는 실수값들로 채워져 공간 효율성이 매우 높습니다.
* **잠재 의미 반영 (Latent Semantics)**: 각 차원은 사람이 직접 정의하지 않고, 모델이 학습 과정에서 데이터로부터 자율적으로 추출한 다차원적 맥락 특징(Feature)을 의미합니다.

---

### 3. 임베딩 좌표 결정 및 유사도 측정

#### 3.1. 좌표(좌표값)는 어떻게 결정되는가?
- 개발자가 특정 좌표값(예: 사과는 x=1.2, y=3.4)을 직접 지정하지 않습니다.
- Word2Vec, GloVe, Transformer 기반 모델 등에서 **"비슷한 맥락(Context)에서 자주 등장하는 단어는 유사한 의미를 갖는다"**는 분포 가설(Distributional Hypothesis)에 따라 **역전파(Backpropagation)와 가중치 업데이트**를 거쳐 자동으로 최적의 좌표 위치를 학습합니다.

#### 3.2. 의미적 유사도 계산: 코사인 유사도 (Cosine Similarity)
고차원 벡터 공간에서 두 단어/문장 벡터 간의 사잇각($\theta$)을 통해 의미적 유사성을 측정합니다.

$$\text{Cosine Similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|} = \frac{\sum_{i=1}^{n} A_i B_i}{\sqrt{\sum_{i=1}^{n} A_i^2} \sqrt{\sum_{i=1}^{n} B_i^2}}$$

* **1에 가까울수록**: 두 벡터가 가리키는 방향이 유사함 (의미가 매우 비슷함)
* **0에 가까울수록**: 두 벡터가 직교함 (의미적 연관성이 없음)
* **-1에 가까울수록**: 두 벡터가 반대 방향을 가리킴 (의미가 반대임)

### 🔄 희소 표현(Sparse) vs 분산 표현(Distributed)

컴퓨터가 자연어를 이해하기 위해 텍스트를 수치화(Vectorization)할 때 사용하는 두 가지 핵심 표현 방식을 비교합니다.

| 비교 항목 | 희소 표현 (Sparse Representation) | 분산 표현 (Distributed Representation) |
| :--- | :--- | :--- |
| **개념** | 전체 단어장 크기의 차원에서 해당 단어 위치에만 `1`, 나머지는 `0`으로 나타내는 방식 | 단어의 의미적 특징을 고정된 N차원의 연속된 실수(Float) 좌표에 나누어 담는 방식 |
| **대표 기법** | 원-핫 인코딩 (One-Hot Encoding), Bag of Words | Word2Vec, GloVe, FastText, BERT/GPT 임베딩 |
| **데이터 형태** | 대부분 `0`으로 채워진 **이진 벡터** | 0이 아닌 유의미한 수치로 채워진 **밀집 실수 벡터** |
| **벡터 차원** | 단어장 크기 $N$에 비례 (수만~수십만 차원) | 고정된 저차원 (보통 128, 512, 768차원 등) |
| **공간 효율성** | 메모리 낭비 심함 (Sparsity 문제) | 공간 효율성 매우 높음 |
| **의미적 유사도** | **계산 불가** (모든 단어가 공간상 직교함) | **계산 가능** (코사인 유사도 등을 통해 단어/문맥 간 거리 측정) |
| **연산 가용성** | 단어 간 관계 연산 불가 | 벡터 연산 가능 (예: `왕` - `남자` + `여자` $\approx$ `여왕`) |

---
### ❓ OOV (Out-Of-Vocabulary, 단어장 미등록 단어)

자연어 처리 모델이 학습 시점에 접하지 못해 사전(Vocabulary)에 등록되지 않은 단어가 입력으로 들어오는 현상 및 해당 단어를 의미합니다.

---

#### 1. 발생 원인 및 문제점
* **발생 원인**: 신조어, 줄임말, 오탈자, 도메인 특화 전문 용어, 메모리 한계로 인한 단어장 크기 제한(Top-N 단어만 사용) 등
* **문제점**: 
  * 모델이 알지 못하는 단어는 미지의 토큰인 **`<UNK>` (Unknown)**으로 대체되어 단어 본연의 정보와 의미를 잃게 됩니다.
  * 결과적으로 문맥 파악 능력이 크게 떨어지고 다운스트림 태스크(분류, 생성 등)의 성능 저하로 이어집니다.

---

#### 2. OOV 해결 기법 (Solutions)

| 해결 기법 | 동작 원리 | 특징 및 효과 |
| :--- | :--- | :--- |
| **서브워드 토크나이저<br>(Subword Tokenization)** | 단어를 더 작은 의미 단위(접두사, 어근, 접미사 등)로 쪼개어 단어장을 구성 | 처음 보는 단어도 조합을 통해 처리 가능<br>(예: `unfriendly` $\rightarrow$ `un` + `friend` + `ly`) |
| **BPE / WordPiece / SentencePiece** | 자주 등장하는 글자 쌍(n-gram)을 병합해 가며 서브워드 사전을 구성 | Modern NLP(BERT, GPT, LLaMA 등)의 표준 토크나이저 방식 |
| **FastText** | 단어를 내부 글자 단위 n-gram의 집합으로 학습 | 사전에 없는 단어라도 내부 글자 조각들의 벡터를 합산하여 OOV 단어의 위치 추정 |

### 📊 서브워드 및 통계 기반 토크나이저 3종 비교 (Tokenizer Comparison)

한국어 및 다국어 NLP 전처리 및 모델링에서 핵심적으로 사용되는 대표적인 토크나이저 3가지의 동작 원리와 특성을 비교합니다.

| 비교 항목 | Byte Pair Encoding (BPE) | WordPiece Model (WPM) | soynlp |
| :--- | :--- | :--- | :--- |
| **핵심 매커니즘** | **빈도 기반 병합**: 가장 자주 함께 등장하는 연속된 글자 쌍(Pair)을 반복 통합 | **우도 기반 병합**: 두 서브워드를 합쳤을 때 언어 모델의 확률(Likelihood) 증가량을 측정해 병합 | **통계 기반 단어 경계 추출**: 어휘 사전 없이 말뭉치의 단어 응집도(Cohesion)와 엔트로피로 단어 경계 판단 |
| **기준 지표** | 출현 빈도수 (Frequency) | 점수(Score) = $\frac{\text{Freq}(AB)}{\text{Freq}(A) \times \text{Freq}(B)}$ | 응집 확률 (Cohesion Score) & 브랜칭 엔트로피 (Branching Entropy) |
| **서브워드 식별자** | 분론적 표기 방식 (모델 구현체마다 차이 있음, 예: GPT는 `Ġ` 사용) | 단어 내부 서브워드 앞에 접두사 `##` 부여 (예: `un` + `##friendly`) | 별도 서브워드 기호 없음 (어근/조사/어미 단위 분리) |
| **OOV 처리 방식** | **완벽 대응**: 최악의 경우 글자(Character) 단위까지 분해하여 처리 | **완벽 대응**: 글자 조각 단위 조합으로 미등록 단어 처리 | 데이터 세트 내 통계가 부족한 단어는 추출 불가 (Corpus 의존적) |
| **학습 및 분할 속도** | 매우 빠름 (단순 빈도 카운팅 기반) | 상대적으로 느림 (매 단계 확률 및 우도 계산 필요) | 데이터 크기에 비례하여 초기 통계 수집 시간 소요 |
| **주요 사용 언어** | 영어, 알파벳 기반 다국어 | 영어, 알파벳 기반 다국어, 한국어 (KoBERT 등) | **한국어 전용** (미정제 대화체, 댓글, SNS 데이터) |
| **대표 활용 사례** | GPT 계열, RoBERTa, LLaMA, Whisper | BERT, DistilBERT, ELECTRA | 비지도학습 기반 한국어 텍스트 정제 파이프라인 |

---

#### 💡 토크나이저 선택 가이드
1. **생성형 LLM 및 일반적인 다국어 모델 구축 시**: OOV 처리가 완벽하고 연산 효율이 높은 **BPE** 계열 사용
2. **BERT류의 마스크드 언어 모델(MLM) 구축 시**: 의미적 연관성을 높인 서브워드를 형성하는 **WordPiece** 사용
3. **한국어 신조어/오탈자/대화체 데이터를 전처리할 때**: 정규 품사 사전에 없는 단어(예: `반포한강공원`, `가성비갑`)를 자율적으로 단어로 추출하고 싶다면 **soynlp** 활용

### ✂️ 토큰화 방식 비교: 공백 기반 vs 형태소 기반

한국어와 같은 교착어를 처리할 때 단어를 어떤 단위로 자를지에 대한 대표적인 두 가지 접근 방식을 비교합니다.

| 비교 항목 | 공백 기반 토크나이저 (Whitespace-based) | 형태소 기반 토크나이저 (Morpheme-based) |
| :--- | :--- | :--- |
| **분할 기준** | 단순히 **띄어쓰기(공백)**만을 기준으로 텍스트 분할 | 뜻을 가진 가장 작은 말의 단위인 **형태소(어근, 조사, 어미 등)** 단위로 분할 |
| **처리 방식** | Python의 `text.split()`과 같이 단순 표면적 분리 | KoNLPy(Okt, Mecab, Komoran) 등 언어학적 규칙/사전 기반 분리 |
| **장점** | 처리 속도가 매우 빠르고 별도의 라이브러리/사전 필요 없음 | **한국어 어휘 파악에 최적화**: 조사/어미를 분리하여 단어의 본래 의미 유지 |
| **단점** | **Vocabulary 폭발**: 동일한 단어도 조사가 다르면 다른 단어로 인덱싱됨 | 형태소 분석 엔진 로딩 및 분석에 따른 추가 계산 비용 발생 |
| **적용 결과** | `"나는 밥을 먹었다"` $\rightarrow$ `['나는', '밥을', '먹었다']` | `"나는 밥을 먹었다"` $\rightarrow$ `['나', '는', '밥', '을', '먹', '었다']` |

### 💡 텍스트 전처리 및 벡터화 파이프라인 (Tokenization vs Embedding)

자연어 처리(NLP) 파이프라인은 **'토크나이저의 정수 인덱싱'**과 **'모델 내 Embedding 레이어의 차원 벡터화'** 2단계로 구분되어 작동합니다.

---

#### 1. 토크나이저 단계 (`sp_tokenize` 함수)
* **역할**: 원본 텍스트를 단어장(Vocab) 기준의 **정수 ID(Integer Index) 시퀀스**로 맵핑하고 길이를 정규화합니다.
* **작동 과정**:
  1. **인코딩**: 텍스트 문장을 미리 학습된 단어장 번호로 변환 (예: `"영화 재밌다"` $\rightarrow$ `[42, 108, 9]`)
  2. **Truncation**: `max_len(50)` 초과 분량 자르기
  3. **Padding**: 부족한 길이는 `0`(`[PAD]` 토큰)으로 채워 고정 길이(50) 형성
* **특징**: 메모리 효율성을 위해 텍스트를 고차원 벡터로 직접 바꾸지 않고, 가벼운 1차원 정수 배열 형태(`shape=(50,)`)로 출력합니다.

---

#### 2. 모델 벡터화 단계 (Keras `Embedding` Layer)
* **역할**: 정수 ID 시퀀스를 받아서 의미적 거리가 반영된 **밀집 벡터(Dense Vector)**로 변환합니다.
* **작동 과정**:
  * 모델의 첫 번째 레이어인 `Embedding(vocab_size=8000, embedding_dim=128)`이 실행됩니다.
  * 입력된 정수 번호(예: `42`)를 128차원의 실수 공간에 맵핑하여 `(50, 128)` 차원의 2차원 행렬을 생성합니다.
* **특징**: 단어의 의미적 유착 관계(벡터 표현)는 토크나이저가 아닌 **GPU 기반의 딥러닝 모델 학습(Backpropagation) 과정에서 최적화**됩니다.

---

```text

  ▼  (1단계: sp_tokenize)

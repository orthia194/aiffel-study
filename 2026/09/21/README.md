## 1. Instruction Following (지시 이행 능력)

**Instruction Following**은 모델이 사용자가 내린 **복잡하고 구체적인 요구사항(지시문)을 정확히 이해하고, 그 형식과 조건에 맞춰 답을 생성하는 능력**을 의미합니다.

* **핵심 개념**: 단순히 다음 단어를 확률적으로 예측하는 언어 모델(Base Model)을 넘어, "요약해 줘", "JSON 형식으로 출력해 줘", "A 조건은 제외하고 B만 답변해 줘" 같은 **제약 조건(Constraints)을 준수**하는 능력입니다.
* **어떻게 학습되는가?**: 주로 SFT(Supervised Fine-Tuning, 지시 미세조정)와 RLHF(Human Feedback 기반 강화학습)를 통해 학습됩니다.
* **왜 중요한가?**: 모델의 추론 능력(Reasoning)이 아무리 뛰어나도 지시 이행 능력이 떨어지면, 원하는 양식이나 제약 조건을 어겨 실제 서비스나 에이전트 시스템에 적용하기 어려워집니다.

---

## 2. Multi-step Reasoning (다단계 추론 능력)

**Multi-step Reasoning**은 단번에 정답을 낼 수 없는 복잡한 문제(수학 문제, 논리 퀴즈, 복잡한 코드 작성 등)를 **여러 개의 중간 단계(Intermediate Steps)로 쪼개어 차근차근 해결해 나가는 능력**입니다.

* **핵심 개념**: 인간이 "이 문제를 풀려면 먼저 A를 구하고, 그 결과를 B에 대입한 뒤 C를 계산해야겠다"라고 생각하는 과정과 같습니다.
* **대표적인 기법 (CoT, Chain of Thought)**:
* 모델에게 단순히 `질문 -> 정답`을 요구하는 것이 아니라, `질문 -> 중간 생각 과정 -> 정답`의 형태로 프롬프팅(Prompting)하거나 미세조정하여 논리적 비약을 막는 기법입니다.


* **왜 중요한가?**: 복잡한 문제일수록 한 번에 정답을 예측하려 하면 환각(Hallucination)이나 논리적 오류가 발생할 확률이 극도로 높아지기 때문입니다.

---

## 3. "그렇다면 작은 모델(Small LLM)에서는 CoT가 안 되는 걸까?"

언급하신 PaLM(540B) 논문 당시에는 "CoT에 의한 성능 비약(Emergent Ability)은 100B 이상의 초거대 모델에서만 나타난다"는 것이 일반적인 통설이었습니다. 작은 모델에 CoT 프롬프팅을 적용하면 오히려 이상한 문맥을 만들어내며 오답을 내는 경우가 많았기 때문입니다.

하지만 이후 연구(Distillation, Fine-Tuning 등)를 통해 이 한계가 깨졌습니다.

1. **지식 증류 (CoT Knowledge Distillation)**
* GPT-4나 PaLM 같은 초거대 모델이 생성해낸 '단계별 생각 과정(CoT 데이터셋)'을 추출합니다.
* 이 고품질의 CoT 데이터를 7B~13B 수준의 **작은 모델에 미세조정(Fine-Tuning) 학습**을 시킵니다.


2. **결과**
* 단순 프롬프팅(Zero-shot/Few-shot CoT)만으로는 7B 모델이 스스로 단계별 추론을 못 하지만, **CoT 방식으로 미리 학습된 7B/8B 모델(예: Llama-3, Qwen 시리즈 등)은 소형 사이즈임에도 매우 뛰어난 Multi-step Reasoning 및 Instruction Following 능력을 발휘**하게 됩니다.



---

### 요약하자면

* **Instruction Following**: "지시한 규칙과 형식을 얼마나 똑똑하게 잘 지키는가?"
* **Multi-step Reasoning**: "복잡한 논리 문제를 단계별로 쪼개서 풀어내는 힘이 있는가?"
* **소형 모델에서의 가능성**: 과거엔 초거대 모델의 전유물이었으나, 현재는 **CoT 데이터 기반의 Fine-Tuning/Distillation 기술** 덕분에 7B~14B급의 작은 모델에서도 강력한 다단계 추론과 지시 이행이 가능해졌습니다.

---

## Emergent Abilities (발현적/창발적 능력)

### 1. 정의

모델의 크기(파라미터 수, 연산량, 데이터 양)를 키울 때, 작은 스케일에서는 전혀 나타나지 않다가 **특정 임계점(Threshold)을 넘어서는 순간 갑자기 벼락처럼 나타나는 고차원적 지능/능력**을 의미합니다.

* **비선형적 도약**: 성능이 비례해서 느리게 올라가는 게 아니라, 정답률 0% 수준에서 특정 크기(예: 100B+)를 넘으면 60~70% 이상으로 **수직 상승**합니다.

---

### 2. 왜 이런 현상이 일어나는가? (A~E 공식 원리)

복잡한 문제를 풀기 위해 $A, B, C, D, E$라는 5가지 서브 공식(Sub-skills)이 모두 필요하다고 가정할 때:

* **작은 모델**: $A, B, C, D$까지 깨우쳤지만, 마지막 $E$가 없어 문제 결과는 계속 0점(정답률 0%)으로 측정됩니다.
* **임계점 도달**: 모델 크기를 더 키워 마침내 **마지막 조각인 $E$ 공식**을 얻는 순간, 기존의 $A, B, C, D$와 폭발적인 연쇄작용(Synergy)을 일으키며 수많은 문제들을 한꺼번에 풀어내기 시작합니다.

---

### 3. 대표적인 Emergent Ability 종류

* **Multi-step Reasoning (CoT)**: 복잡한 수학이나 논리 문제를 단계별로 쪼개어 풀어나가는 능력
* **In-Context Learning (Few-shot)**: 가중치 업데이트(파인튜닝) 없이 프롬프트의 예시 몇 개만 보고 새로운 규칙을 즉시 학습하는 능력
* **Instruction Following**: 복잡한 제약 조건과 출력 양식(JSON 등)을 엄격하게 준수하는 능력

---

### 4. 최근 학계/산업계의 시각 변화

* **초기 통설 (2022년 PaLM 등)**: "100B 이상의 초거대 모델에서만 나타나는 전유물이다."
* **현재 시각**:
1. **지식 증류(Distillation)** 및 고품질 CoT 데이터 학습 기술이 발전하면서, **7B~14B 수준의 소형 모델(SLM)에서도 Emergent Ability를 재현**해내고 있습니다.
2. 평가 방식이 단답형(0 또는 1)이라 갑자기 꺾여 올라가는 것처럼 보였을 뿐, 모델 내부의 확률적 추론 능력은 차근차근 축적되고 있었다는 분석도 힘을 얻고 있습니다.

---

## RLHF의 탄생 배경

GPT-3 같은 기존의 사전 학습 언어 모델(Base Model)은 인터넷의 방대한 글을 보고 "다음에 올 단어를 가장 확률 높게 맞추는 기계"에 불과했습니다.

이로 인해 3가지 치명적인 문제가 발생했습니다.

* **지시 불이행 (Misalignment)**: "이 문장 요약해 줘"라고 했더니 요약을 안 하고 그 뒤에 이어질 법한 엉뚱한 소설을 이어서 써버림.
* **유해성 및 편향 (Toxicity/Bias)**: 인터넷의 부적절한 글이나 혐오 표현을 그대로 배워서 출력함.
* **환각 현상 (Hallucination)**: 거짓 정보를 당당하게 사실처럼 말함.

이 문제를 해결하기 위해 **"인간이 선호하고 도움이 되는 방식(Helpful, Honest, Harmless)으로 모델의 행동을 교정하자!"** 해서 등장한 기법이 RLHF (Reinforcement Learning from Human Feedback, 인간 피드백 기반 강화학습)입니다.

---

## 1. InstructGPT : RLHF, 언어모델과 강화학습의 만남

OpenAI가 GPT-3에 RLHF 기법을 최초로 적용하여 만든 모델이 바로 **InstructGPT**입니다.

* 단순히 인터넷 글로 학습한 GPT-3보다 **파라미터 수가 100배 이상 작은 InstructGPT(1.3B)가 사람들의 지시를 훨씬 잘 따르고 선호도가 높다**는 것을 증명했습니다.
* 우리가 잘 아는 **ChatGPT(GPT-3.5/4)의 근간이 된 핵심 논문이자 기술**입니다.

---

## 2. InstructGPT 학습 3단계

InstructGPT는 크게 **3단계 파이프라인**을 거쳐 완성됩니다.

```
[1단계: SFT]  --->  [2단계: RM]  --->  [3단계: RL]
(기초 예의범절)     (채점관 만들기)     (강화학습 반복)

```

### 1단계 : SFT (Supervised Fine-Tuning, 지도 미세조정)

* **역할**: 모델에게 "사람의 질문에는 이렇게 답하는 거란다" 하고 기초 양식을 가르치는 과정.
* **방법**: 사람이 직접 작성한 고품질의 `[질문 - 정답 답변]` 데이터셋을 가지고 사전 학습 모델(Base Model)을 미세조정합니다.
* **한계**: 사람이 답안지를 일일이 다 써줘야 하므로 대량의 데이터를 만드는 데 비용과 시간이 너무 많이 듭니다.

### 2단계 : RM (Reward Model, 보상 모델 학습)

* **역할**: 모델이 낸 답변이 얼마나 좋은지 평가하는 '자동 채점관(AI 채점기)'을 만드는 단계.
* **방법**:
1. 하나의 프롬프트에 대해 SFT 모델이 여러 개의 답변(예: A, B, C, D)을 생성하게 합니다.
2. 사람이 그 답변들을 읽어보고 **"A > B > D > C"** 순서로 순위를 매깁니다.
3. 이 순위 데이터를 학습시켜, 답변을 넣으면 점수(Score)를 계산해 주는 보상 모델(RM)을 완성합니다.

### 3단계 : RL (Reinforcement Learning, PPO를 이용한 강화학습)

* **역할**: 2단계에서 만든 채점관(RM)을 붙여놓고 모델이 점수를 높게 받도록 반복 학습(스스로 개과천선).
* **방법**:
1. 언어 모델이 프롬프트를 보고 답변을 생성합니다.
2. 2단계의 보상 모델(RM)이 그 답변을 평가해 점수(보상)를 줍니다.
3. 강화학습 알고리즘인 PPO (Proximal Policy Optimization)를 사용해, 점수를 더 많이 받는 방향으로 언어 모델의 가중치를 업데이트합니다.

* *(이때 기존 1단계 모델에서 너무 멀어져 이상한 소리를 하지 않도록 KL-Divergence Penalty라는 억제 장치를 함께 사용합니다.)*

---

### 요약하자면

1. **SFT**: 사람이 작성한 답안지로 **기초 대화법**을 배우고,
2. **RM**: 사람들의 선호도 순위 데이터를 보고 **답변 채점기**를 만든 뒤,
3. **RL**: 채점기한테 칭찬(높은 보상)을 받으려고 스스로 답변을 개선하며 **최종 완성**되는 구조입니다.

## 2. 3대 핵심 차이점 상세 분석

### ① 모델 아키텍처 (MoE vs Dense)

* **GPT-4 (MoE 구조)**: 여러 개의 전문화된 소형 모델(Expert)들을 모아놓고, 질문이 들어올 때마다 필요한 전문가 모델 2개 정도만 호출해 답변을 만듭니다. 덕분에 수천억~조 단위의 엄청난 지식을 가졌으면서도 **연산 속도와 효율성**을 극적으로 챙길 수 있습니다.
* **LLaMA (Dense 구조)**: 모델 전체 가중치가 연결된 단일 통짜 구조입니다. LLaMA 3에 이르러서는 405B(4,050억 파라미터)라는 초거대 Dense 모델까지 성공적으로 학습시켜, 오픈소스 모델도 GPT-4급 성능에 도달할 수 있음을 증명했습니다.

### ② alignment(정렬) 및 학습 3단계 방식의 차이

두 모델 모두 `1단계 SFT → 2단계 RM → 3단계 RL/RLHF`라는 큰 틀의 방향성은 동일합니다.

* **GPT-4**: 수많은 사람 데이터 라벨러와 다중 보상 모델(RM)을 붙여 **환각, 유해성, 안전 가이드라인 준수**를 극도로 가다듬은 매우 정교한 PPO 기반 RLHF를 적용했습니다.


* **LLaMA**: "대량의 데이터보다 **수천 건의 초고품질 SFT 데이터**가 낫다"는 기조를 세웠습니다. 또한 2~3단계를 복잡하게 거치는 PPO 방식 대신, 보상 모델 없이 선호 데이터로 직접 가중치를 업데이트하는 **DPO(Direct Preference Optimization)** 기법을 적극 도입하여 가볍고 빠르게 RLHF 효과를 냈습니다.



### ③ 데이터 보안과 비용 구조 (On-Premise vs Cloud API)

* **GPT-4**: 초기 인프라 구축비용은 0원이며 API를 쓴 만큼 돈을 냅니다. 단, 사내 기밀이나 개인정보가 포함된 데이터를 보낼 경우 데이터 유출에 대한 우려가 존재합니다.
* **LLaMA**: GPU 인프라 구축 또는 대여 비용이 들지만, 한 번 구축해 두면 **호출 건수가 수억 건이 되어도 추가 API 비용이 발생하지 않습니다.** 무엇보다 회사 내부망(On-Premise)에서 돌릴 수 있어 **데이터 보안이 완벽**합니다.

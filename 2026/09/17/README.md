### 1. AllenNLP (Allen Institute for AI)

> **"학술 연구 및 서체/구조적 실험을 위한 프레임워크"**

ELMo 모델 발표 당시 유명해진 프레임워크로, PyTorch 기반 위에 구축되어 NLP 연구자들이 논문용 모델을 설계하기 좋게 만든 도구입니다.

* **장점**:
* 객체지향 설계가 매우 깔끔하여 NLP 파이프라인의 각 단계(Tokenize, Embed, Encoder, Decoder)가 모듈화되어 있습니다.
* JSON 설정 파일(`config.json`)만으로 모델 실험 환경을 정의할 수 있어 연구용 실험 관리가 편했습니다.


* **단점**:
* 설정 파일 방식이 독이 되어, 조금만 커스텀하려고 하면 프레임워크 내부 구조를 깊게 파야 해서 진입 장벽이 높았습니다.
* 생태계 확장에 실패하며 현재는 거의 사용되지 않고 사실상 유지보수가 중단된 상태입니다.



---

### 2. Fairseq (Meta / Facebook AI Research)

> **"시퀀스-투-시퀀스(Seq2Seq) 및 대규모 모델 연구의 공장"**

메타(Meta)에서 번역, 음성 인식, 대규모 트랜스포머 연구(RoBERTa, BART, Wav2Vec 등)를 위해 직접 만든 PyTorch 기반 프레임워크입니다.

* **장점**:
* **C++ 레벨의 극대화된 성능**: 분산 학습(Multi-GPU) 및 대규모 데이터 처리 속도가 매우 뛰어납니다.
* 메타에서 발표하는 최신 AI 논문의 공식 구현체가 대부분 Fairseq로 공개되었기 때문에 최신 연구를 가장 먼저 접할 수 있었습니다.


* **단점**:
* CLI(터미널 명령어) 위주의 사용법과 복잡한 파라미터 구조 때문에 학습 곡선이 매우 가파릅니다.
* 코드 베이스가 무겁고 파이썬 라이브러리처럼 직관적으로 가져다 쓰기 힘듭니다.


* **현재 위상**: 여전히 메타 내부 연구 및 음성/다중모달(Multimodal) 연구에서 쓰이지만, 일반적인 NLP/LLM 실무에서는 Hugging Face로 옮겨갔습니다.

### 3. Fast.ai

> **"딥러닝계의 jQuery / High-Level Wrapper"**

"모두를 위한 딥러닝"을 슬로건으로, 초보자도 몇 줄의 코드로 최신 기법(Best Practices)이 적용된 모델을 만들 수 있게 해주는 프레임워크입니다.

* **장점**:
* **최고의 생산성**: Learning Rate Finder, Fit One-Cycle 기법 등 성능을 올려주는 최적화 기법들이 기본 적용되어 있어서 코드 몇 줄로 고성능 모델 생성이 가능합니다.
* 입문자나 비전공자가 빠르게 아이디어를 구현해 보기에 최적입니다.


* **단점**:
* 내부 동작이 너무 많이 숨겨져 있어(Abstraction), 정밀한 모델 개조나 Low-Level 디버깅이 어렵습니다.
* 자체 커스텀 데이터 구조(`DataLoaders`) 사용을 강제하는 경향이 있어 실무 커스텀 파이프라인 구축 시 답답할 수 있습니다.

### 4. Tensor2Tensor (Google)

> **"트랜스포머(Transformer) 아키텍처가 세상에 태어난 고향"**

구글이 2017년 *"Attention Is All You Need"* 논문을 발표하면서 트랜스포머 코드를 함께 공개했던 TensorFlow 기반 프레임워크입니다.

* **장점**:
* 트랜스포머 구조의 최초 공식 구현체로서 NLP 역사에 큰 족적을 남겼습니다.
* 번역, 요약, 이미지 생성 등 다양한 시퀀스 과제를 하나의 엔진으로 처리하려는 시도였습니다.


* **단점**:
* TensorFlow 1.x 기반으로 작성되어 직관성이 떨어지고 사용하기 매우 까다로웠습니다.


* **현재 위상**: 구글에서도 Tensor2Tensor를 폐기하고, 현재는 TensorFlow 2.x/JAX 기반의 **Trax** 및 **Flax** 생태계로 전환되었습니다.

이번 이미지에 나온 도구들은 **텍스트 전처리(Preprocessing) 전용 라이브러리**들입니다.

결론부터 말씀드리면, NLTK와 KoNLPy는 트랜스포머/LLM 시대 이전부터 내려온 대표적인 '전통적 텍스트 전처리 도구'입니다.

강사님이나 노드에서 잘 보라고 한 이유와, 현재 실무에서의 위치를 깔끔하게 정리해 드릴게요.

---

### 1. KoNLPy (코엔엘파이 - 한국어 전처리 필수 도구)

> **"한국어 형태소 분석의 조상님이자 기준점"**

한국어는 영어와 달리 "나+는", "밥+을", "먹+었+다"처럼 조사와 어미가 붙는 **교착어**이기 때문에, 띄어쓰기 단위로 쪼개면 모델이 잘 학습하지 못합니다.

* **역할**: 한국어 문장을 형태소(뜻을 가진 가장 작은 단위) 단위로 쪼개고, 품사(명사, 동사, 형용사 등)를 태깅해 줍니다. (내부에 `Okt`, `Mecab`, `Kkma`, `Hannanum` 등 여러 분석기가 들어있음)
* **왜 잘 봐야 할까요?**:
1. **데이터 탐색(EDA) 및 정제**: 모델에 넣기 전에 "우리 데이터에 어떤 명사 키워드가 제일 많이 나오지?" 하고 **텍스트 통계를 내거나 불용어(Stopwords)를 제거할 때** 여전히 최고입니다.
2. **검색 엔진 및 RAG 하이브리드 검색**: 최신 LLM RAG 구축 시, 키워드 기반 검색(BM25)을 결합할 때 형태소 분석기(Mecab 등)를 쓰는 경우가 아주 많습니다.



---

### 2. NLTK (Natural Language Toolkit)

> **"영어 NLP의 교과서이자 종합 선물 세트"**

영어 텍스트 다룰 때 필요한 모든 전처리 기능(단어 쪼개기, 불용어 제거, 어간 추출 등)이 들어있는 파이썬 대표 라이브러리입니다.

* **역할**: 영어 문장 토큰화, 어간 추출(Stemming), 표제어 추출(Lemmatization), 품사 태깅 등.
* **왜 잘 봐야 할까요?**:
* 딥러닝 이전의 NLP 기본 개념(토큰화, 정규화, 불용어 등)을 익히기에 가장 좋은 학습용 도구입니다.



---

### 3. 나머지 도구들의 현재 위치

* **SpaCy (스페이시)**:
* 영어/유럽어권에서 **속도가 매우 빠르고 현업 파이프라인에 최적화된 최신 텍스트 전처리 도구**입니다. (NLTK보다 실무에서 훨씬 많이 씀)


* **TorchText (토치텍스트)**:
* **현재는 사실상 폐기(Deprecated)되었습니다.** PyTorch 공식 팀에서 유지보수를 중단했으므로, 학습용 노드에 있더라도 "옛날엔 이런 걸 썼구나" 하고 넘어가시면 됩니다.



---

### 💡 트랜스포머(BERT/LLM) 토크나이저와 무슨 차이가 있나요?

질문자님이 1개월 차에 직접 만들어보셨던 BPE(Byte Pair Encoding)나 **WordPiece** 같은 Subword 토크나이저와 이 도구들의 차이를 아는 것이 중요합니다.

```text
[ 입력 문장 ]: "나는 영화가 너무 재미있었다."

1. KoNLPy (Mecab/Okt) 형태소 분석:
   -> ['나', '는', '영화', '가', '너무', '재미있', '었', '다'] (문법 규칙 기반 분할)

2. BERT / Hugging Face (Subword / BPE):
   -> ['나', '##는', '영화', '##가', '너무', '재미', '##있었다'] (통계/빈도수 기반 분할)

```

* **KoNLPy/NLTK**: 문법 규칙이나 사전(Dictionary)을 기준으로 단어를 쪼갭니다. 사전 없는 신조어에 약합니다.
* **Hugging Face / LLM**: 데이터 통계 기반으로 자주 붙어 나오는 글자 조합(Subword)을 쪼갭니다. 신조어나 OOV(Out of Vocabulary) 문제에 매우 강합니다.

---

### 🎯 요약 및 학습 가이드

* **실제 트랜스포머/LLM 모델 입력용**: **Hugging Face 토크나이저**를 씁니다. (KoNLPy나 NLTK로 쪼갠 걸 모델에 바로 넣지는 않습니다.)
* **데이터 분석, 키워드 추출, 텍스트 정제, RAG 검색**: KoNLPy (특히 Mecab/Okt)와 **NLTK/SpaCy**를 아주 유용하게 가져다 씁니다.
